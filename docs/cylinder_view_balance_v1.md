# Cylinder 物理视角平衡对照 V1

## 预先锁定的实验设计

本轮接续 [Cylinder 底视图诊断](cylinder_bottom_view_audit_20260910.md)。真实 Cylinder 数据目前不在本地，所有结果只针对合成数据。目标是检验补充物理视角覆盖是否有用，不在本轮同时改变 encoder、尾巴监督、时序、联合损失或实例关联架构。

- 原始 768/15k checkpoint 初始化，两组同权重、同 seed 17、同固定 lr=3e-6，各 800 步。
- 冻结 VGGT-Omega encoder；训练原有 shared adapter、深度头、Core23 多实例头。联合特征开关 off，无新增几何/不确定性/尾曲线损失。
- 50% 更新来自原训练动作 ClimbWall 的 16 个姿态；25% 来自原训练双鼠 8 个姿态；25% 来自原 Sample10 两个外观/场景数据集各 8 个姿态。
- ClimbWall 更新交错覆盖 V=1/2/3/4。`side_control` 仅选择物理侧视；`balanced_views` 的单目交替顶/底，双目侧＋顶/底，三/四目覆盖顶＋底＋侧。
- 两组每一步的源场景、视图数量、分辨率相同，回放完全相同，仅 ClimbWall 相机子集改变。每组 1,800 张图像；实际 patch-token 数由日志核验相等。
- 原始相机对的基线是每个场景的固定深度/世界坐标归一化尺度。增加或减少视图不改变 GT 尺度；相机方向由外参计算，不假设 id 0 总是顶视。
- 768 长边并保留原长宽比；Cylinder 768×768，Homecage 768×432。缓存绑定完整相机顺序/子集，32 GiB CPU LRU，无新磁盘特征缓存。

原图清晰度限制：抽查 ClimbWall/WashFace 底视 JPEG 是 **512×512**，本轮上采样至 768；Sample10 的底视原图为 **1024×1024**，下采样至 768。因此“768 输入”不等于 ClimbWall/WashFace 已有 768 原生细节。本轮控制只改变采样，不新增渲染；后续必要时应单独验证更高原生分辨率或 ROI。

## 验证与标定

保留全部原有 32 个验证场景的原始相机对；从其中 16 个 WashFace 姿态选 8 个，新增底视单目、顶视单目、侧视单目、侧＋底、两侧＋底、两侧＋顶、两侧＋底＋顶，共 **88 个场景-视角组合**。这是重用开发集，不是独立测试集；训练与验证按动作/源视频分组不交叉。

每组分别报告全 Core23 NME、检测感知 PCK、非尾部 16 点 NME、身体深度 AbsRel、身体深度 Spearman，并按物理方向分解。

相机头禁用。3D 诊断明确使用 Blender K/E：在单鼠多视图中，用 GT 框辅助 query 匹配、预测 objectness≥0.5、数据有效位及均匀鲁棒射线三角化。报告覆盖率和支持子集上的身体误差，单位标为 native Blender world units，不未经核对称作毫米。单目不产生三角化 3D。该流程不是端到端实例关联，也没有把 K/E 注入 VGGT 注意力，因此不能声称已解决跨视角特征融合。

## 决策门槛（相对原 checkpoint）

1. 底视单目和侧＋底中的底视：身体 NME 至少改善 10%。均衡组还须分别优于等预算侧视对照至少 5%。
2. 原 Cylinder 侧视对、原双鼠对：全 Core23 NME 不恶化超过 5%，检测感知 PCK 不下降超过 0.03，身体深度 AbsRel 不恶化超过 10%。
3. 底视各输入组合的身体深度 AbsRel 不恶化超过 10%。
4. 顶视单目、两侧＋顶、四视图中的顶视身体 NME 不恶化超过 5%。

固定最后一步评估，不选开发集最佳 checkpoint，不自动替换现用模型。即使单种子通过也只能说明值得复验，不能认定真实 Cylinder 泛化有效。

## 复现入口

- `configs/experiments/cylinder_view_balance_v1.json`
- `tools/train_cylinder_view_balance.py`：调用未改动的旧 bounded replay engine，仅在本实验进程中安装采样、数据标签和分层评价 wrapper。
- `tools/analyze_cylinder_view_balance.py`：固定门槛、曲线和关键点可视化。
- `tools/verify_cylinder_view_balance.py`：重建协议、数据/代码/权重哈希、逐步配对预算、原验证指标一致性及 checkpoint 重载核验。
- `tests/test_cylinder_view_balance.py`：视角唯一性、物理方向与编号解耦、覆盖和异常输入测试。
- 产物：`output/cylinder_view_balance_v1/`。

尾巴选配关闭暂不引入，防止将视角覆盖与关键点集合变化混在同一对照中。

## 完成结果

两组均已完成，合计 1,600 步，运行约 **478.6 秒（8 分钟）**。每组精确 1,800 张图像、3,540,384 个空间 patch token。原权重、72 个源场景和锁定训练代码哈希通过核验；原始 32 个相机对验证指标复现差异为 0。全部验证组合的 GT 投影最大误差 0.000246 px，同一相机的 K/E 和世界标签跨组合保持完全相同。

| 指标（越小越好，PCK 除外） | 原模型 | 等预算侧视对照 | 均衡视角 |
|---|---:|---:|---:|
| 单底视身体 NME | 0.2980 | 0.2646 | **0.1901** |
| 单底视身体深度 AbsRel | 0.2138 | 0.1524 | **0.0599** |
| 单底视检测感知 PCK ↑ | 0.0870 | 0.1304 | **0.2609** |
| 侧＋底中的底视身体 NME | **0.1576** | 0.1755 | 0.2056 |
| 两侧＋底中的底视身体 NME | **0.1411** | 0.1485 | 0.2002 |
| 四视图中的底视身体 NME | **0.1409** | 0.1454 | 0.1926 |
| 单顶视身体 NME | 0.2982 | 0.2578 | **0.1635** |
| 原 Cylinder 侧视对 Core23 NME | 0.1207 | **0.0894** | 0.1233 |
| 原 Cylinder 侧视对 PCK ↑ | 0.4973 | **0.6522** | 0.4538 |
| 原双鼠相机对 Core23 NME | **0.1220** | 0.1310 | 0.1321 |
| 原双鼠相机对 PCK ↑ | **0.5360** | 0.5156 | 0.4844 |

单底视身体误差相对原模型改善 36.2%，相对等预算侧视对照改善 28.2%；深度误差下降 72.0%。身体深度 Spearman 从 0.400 提升到 0.642，说明收益不只是整体距离偏置改变。多视图中的底视深度也改善，但其关键点没有随之改善。

**均衡组仅通过 10/17 个预先声明的门槛，不替换现用模型。** 失败项：侧＋底身体 NME（相对原模型和对照各一项）、旧双鼠 NME/PCK、旧 Cylinder 侧视 PCK、两侧＋顶和四视图中的顶视身体 NME。侧视对照通过 13/15 项，也不是全面可用的替代模型。

视觉检查 `hardest_bottom_pose.png`：选择的是原模型单底视最差的 frame 55，而不是均衡组收益最大的帧。均衡组单目时整体偏向身体一侧的误差缩小，但鼻端/头部仍可明显漂移；这个帧的双视底视有改善，但全 8 帧平均反而退化，不能以单张图代替汇总。

训练曲线仍有缓慢下降，但没有中途开发集评估序列，因此不能从训练 loss 单独断言未收敛或增加步数一定有效。当前已观察到单目收益和多目退化并存，应先定位干扰来源。

## 无需重训的独立视图融合检查

`tools/compare_cylinder_independent_views.py` 复用同一模型已保存的单侧视、单底视预测，与联合输入 `[2,6]` 比较。使用完全相同的 Blender K/E、有效位和三角化阈值，不再运行 encoder、不修改模型。这是事后诊断，不属于预先声明的主门槛。

均衡组的侧＋底 128 个身体点中：

- 联合编码后标定三角化支持 **45/128（35.2%）**。
- 各视图独立预测后标定三角化只支持 **16/128（12.5%）**。
- 两者共同支持仅 4 点，无法据此作稳健的配对精度判断。逐点汇总的支持子集平均误差分别为 22.78 和 25.78 native Blender units，支持集合不同，不能直接作为公平精度排名。

所以“直接把独立单目预测拿来三角化”也不是现成解决方案。准确标定是必要基础，但无法替代跨视角一致的 2D 关键点；本轮也没有引入学习式融合。

## 下一步判断

> 后续 [关键点头隔离对照与组合覆盖审计](cylinder_pose_only_v1.md) 发现：本轮按 pose index 固定组合，ClimbWall 双视图未覆盖验证所用 `[2,6]`，且每个姿态的单目顶/底固定。物理方向边际平衡不等于完整组合覆盖。因此以下模块隔离之外，应优先修正这一采样限制，再决定是否需要架构解耦。

保留新专项验证和物理方向采样能力，但**不直接延长这组相同训练，也不启用未经验证的融合**。更有信息量的下一小步是同数据、同预算下做模块隔离：

1. 仅训练关键点头（冻结共享 adapter 和深度头），与当前三者共同更新对照，检验单/多目关键点退化是否受到共享特征更新影响。
2. 单独评估同一姿态在不同视角子集下的 2D 预测一致性，再决定是否增加一致性约束或轻量解耦分支；这仍是待验证假设，不把本轮相关性当作因果。
3. 视需要另做原生更高分辨率渲染/ROI 对照；当前 512 原图上采样不增加真实细节。真实泛化仍等待真实 Cylinder 数据恢复。

新增/既有 unittest 共 **115 项通过**。协议、源文件、权重、逐步预算和标定坐标核验通过；检查脚本把结果写入 `delivery_verification.json`。所有模型仅保存为实验 checkpoint，未开启后续自动训练。
