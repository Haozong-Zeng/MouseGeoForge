# 底视域适配配对协议 v2

状态补记（2026-10-18）：可行性臂已完成4,000更新，几何门槛未通过；本协议配对尚未运行，完整配对训练器尚待实现。不自动启动冻结对照或关键点。后续如修改数据/目标，先登记新版本并同时应用两臂。见[最终复核与当前路线](bottom_geometry_experiment_roadmap_20261018.md)；原机器可读登记快照不覆盖。

登记日期：2026-10-18。本协议在后续配对实验开始前登记；当前 `pure_geometry_bottom_20261018_v2/geometry_seed17` 是纯几何可行性运行，不追认成新配对实验的一臂。机器可读协议及文件哈希见 `output/bottom_domain_paired_20261018_v2/protocol.json`。

## 执行顺序

1. 当前适配臂按原协议完成并保存最终 raw/EMA、优化器和 RNG。启动器随后退出，**不自动启动冻结对照、关键点训练或其他 GPU 作业**。旧联合训练及其冻结对照继续取消。
2. 汇总未见合成 rig、已知真实 rig 几何和其他视角保留结果，登记是否达到现有几何门槛。损失下降不代替独立验证；预检权重丢弃。
3. 数据加载预检通过后，按本协议重新运行同起点、同数据顺序的几何配对。不能把旧联合臂、当前可行性臂与新冻结臂直接相减。
4. 几何验收后才进入两阶段 2D 定位配对。3D 关键点继续等待几何和 2D 定位验收。当前启动器不承担后续配对的自动调度。

## 相机和数据边界

- PyMouseStudio 九采集只有一个标定装置：几何使用已知 K/E，模型相机输出只作诊断，不把留出采集的相机准确率当作新装置泛化。
- 未知装置相机监督来自真实重新渲染的六训练 rig，以及 DANNCE1；主验收使用两套整 rig 留出的合成配置，训练/验证的规范化相机配置签名不得重叠。只有两套留出 rig，不能宣称广泛真机跨装置能力。DANNCE2 保持 TEST 保护。
- 沿用已固定的训练/验证 manifest、修订标注、完整 rig 尺度和坐标约定。FR3/FR2/AZR2L2 留出标注不训练，其他受保护 TEST 不参与方法选择。每个阶段开始前另存具体 schedule 和 source hashes；两臂必须完全相同。

## 几何配对 G0/G1

两臂均从同一发布权重重新开始，不实例化 KeypointHead。G0 冻结全部 encoder，只更新 camera/depth head；G1 额外解冻最后两个 frame/inter-frame block。confidence 投影和 camera/register 输入 token 均冻结。相机、深度和重投影目标完全相同。

每次更新混合累积 8 微批：2 新 rig、1 既有底视、1 非 Water 回放、2 真实标注、1 DANNCE1/回放交替、1 保留回放。真实标注从第一次更新起占25%，原始视频0%，DANNCE1纯相机6.25%，Water仅3.125%几何回放。全程不做重复单 rig 视频相机监督。

损失权重使用已保存的**发布模型共享 encoder 梯度校准结果**，在两臂复制同一组权重，不在冻结臂重新取倒数，也不根据验证调权。每100更新报告可训练模块的分项梯度，冻结 encoder 的梯度应为零，不能与 G1 的非零梯度混为同一统计。所有更新均先累积后裁剪，阈值10，并报告实际裁剪比例。

head 峰值LR `1e-5`，G1 encoder `1e-6`；500更新 warmup，随后余弦降到10%。每臂固定4,000优化器更新、32,000微批，同seed17、同顺序、同初始化；任何中断不足预算都不作为完整配对。G0/G1 的模型参数集合是唯一实验变量；更新数而非墙钟时间对齐。

## 定位的两阶段配对 H0/H1

进入条件是几何验收通过，并把**通过验收的最终 EMA 几何 checkpoint**及哈希固定；不挑验证最高的中间 checkpoint。若几何未达标，停止向定位和3D推进，不能以定位改善覆盖几何失败。

**阶段一：先训练随机 2D head。** 冻结 encoder 和所有已有几何 head，特征 detach，只训练五点 heatmap head，LR `2e-4`。每更新8微批，其中4真实人工标注、2有完整五点监督的合成底视、2有监督的其他视角；缺少所需标注的数据不消耗定位更新，Water和无对应标注视频不进入此阶段。先审计有效标签池并保存 manifest/schedule，不凭数据集名称认定有标签。

阶段一最多6,000更新，至少1,500更新；每200更新统计固定训练监测样本的定位损失，连续三个窗口相对改善均不足1%才视作训练收敛。该判据只使用训练数据；达到最大预算仍未收敛则记录未收敛，不启动解冻比较。500更新 warmup，余弦到10%，EMA规则见下。此阶段结束保存最终模型、head EMA、优化器和 RNG。

**阶段二：从同一个已收敛 head 分叉。** H0 继续冻结 encoder，仅训2D head；H1 解冻最后两个 frame/inter-frame block。两臂都冻结 camera/depth head 参数，head峰值LR `2e-5`，H1 encoder `1e-6`；相同新建优化器、同seed17、同8微批混合顺序、各2,000更新、500更新warmup及余弦衰减。仅定位目标发生反传；已有几何 head 参数冻结仍不能保证其输出不变，因为共享 encoder 可变，必须复测基础几何和其他视角。

阶段二不再把随机 head 的训练不足归因于域适配。必须报告阶段一最终冻结基线，以及阶段二 H0/H1 的同预算差值。不存在直接从当前几何模型跳到随机 head 联合反传的路径。

## 验证、EMA及判定

EMA使用 `min(0.999,(step+1)/(step+10))`，每500更新验证，最终同时报告raw和EMA；以最终EMA为主，不按中间验证挑checkpoint。分叉时复制同一初始模型/EMA状态，并为两臂使用同一个重新开始的EMA更新计数。

几何门槛沿用纯几何协议：未见合成rig的底视旋转中位数/P95至少改善30%，P95≤10°，方向P95≤15°，预测相机＋深度转移coverage32增加≥5pp；已知rig报告使用给定相机的标注射线重投影；逐来源、其他视角转移及中心化形状不得出现退化。现有可行性运行的门槛不因本次登记而放宽。

定位报告五点逐点误差/PCK8/16/32、可见性与有效点分母、真实底视和其他视角、合成底视和其他视角，并同时复测相机/深度/转移。缺失预测按失败计入固定有效支持。运行口径补记：当前几何转移/人工射线32px阈值统一使用704×768参考坐标，不能把512输入像素或原图原生像素混作同一口径；后续自动定位须在执行前固定其评价坐标并在两臂一致。不能将使用人工源点的几何重投影指标称作自动关键点精度。

每臂报告总体和逐rig/采集/来源结果及配对差值；采集留出不等于装置留出。只有一个seed和两套合成留出rig时不作稳健跨装置统计结论。所有门槛及主要指标在配对运行前固定；训练监测不允许读取受保护TEST。

## 数据加载与吞吐

新增 `tools/geometry_prefetch_20261018.py`：CPU-only DataLoader，`spawn`工作进程，`persistent_workers=True`、`prefetch_factor=2`，每个worker限制torch/OpenCV线程为1；主进程用pinned memory和non-blocking传输。固定schedule本身已包含相机包和采样顺序，DataLoader不再shuffle、不drop、不合批；独立generator避免worker种子消耗模型RNG。

新增 `tools/run_geometry_prefetch_20261018.py` 将加载器接入原纯几何训练循环，使用独立输出目录及runtime哈希凭据；启动预检或训练必须显式指定阶段，结束即退出，无后继臂。它是几何加载入口，**不是已实现的定位两阶段训练器，也不代表配对已经运行**。当前正在运行的臂代码/协议不热改，不为I/O优化中途重置优化器。

0/2/4 workers先做相同样本逐张量bitwise及顺序对照，再做pinned CPU→GPU传输与RNG隔离预检。吞吐报告区分worker启动、纯加载、GPU计算/同步、EMA验证和checkpoint写盘。纯加载1.5–2倍不能当作总训练1.5–2倍；必须用同一schedule和同样优化器更新数做端到端计时。新入口将累计loader等待时间，默认选通过预检的4 workers；若端到端测量没有收益，再记录并调整，不根据瞬时GPU利用率单独下结论。
