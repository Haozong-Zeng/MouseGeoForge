# 256/512 收敛预算对照（预注册）

2026-09-10。承接已完成的 [5000 步分辨率对照](pose_resolution_control.md)。
用户授权推进；本轮检验更长优化预算后双鼠是否仍然失败，不同时引入 ROI、
实例相对坐标、新数据、768 输入、Jon、时序或尾巴曲线损失。

## 固定协议

- 两组均 seed17，64 train / 32 val，保持原场景、源动作分组和两个相机；
  单鼠 256²/512²，双鼠 256×144/512×288，冻结 RGB encoder。
- 从相同原始 checkpoint、相同随机初始化重新训练，不续训单独一个分辨率。
- 各 15000 次更新：1–5000 步 LR=1e-4；5001–15000 步按余弦衰减至 1e-5。
  更新 s 的 LR 为 `1e-5 + (1e-4-1e-5)/2 * (1+cos(pi*(s-5000)/10000))`。
- AdamW、权重衰减 .01、梯度裁剪 1，以及其余模型/损失参数保持不变。
  local heatmap 辅助 loss=0，depth+pose 共同训练但显式 bridge off。
- 每 500 步评估训练集；验证集只记录初始和固定最终结果，不挑选最佳 checkpoint。
- 第一段样本顺序哈希必须与已有 5000 步实验相同；两组全程顺序与 LR 哈希必须相同。
  不承诺 CUDA grid_sample 反向的逐位确定性。
- 这是“训练预算+LR 策略”的联合干预，不把相对旧实验的变化单独归因于步数或 LR。
  两个新组之间只有输入分辨率不同；等步数不等计算量。

配置：`configs/experiments/pose_convergence_{256,512}_15000_v1.json`。
输出：`output/pose_convergence_{256,512}_15000_v1/`。旧结果不覆盖。

## 运行与验收

```bash
.venv-vggt-omega-eval/bin/python tools/run_pose_convergence_queue.py --launch
```

串行队列先 256 训练/重载，再 512 训练/重载，最后生成配对报告和曲线。
状态与每阶段日志位于 `output/pose_convergence_queue_v1/`。
文件锁和独占启动日志防止重复启动；已存在输出拒绝覆盖；失败停止队列，不自动重试。
两组启动前检查源清单、原始计划和分组哈希与旧实验相同；训练仍逐场景检查深度对齐。

完成后必须重载复算每组全部 32 验证场景（容差 1e-6），查看双鼠固定困难帧
40/98（训练）及 246/393（验证）的侧视与顶视。相机顺序以 batch.view_ids 为准，
0=顶视、2=侧视，张量顺序不等于相机编号。

分开报告单/双鼠的 train/val NME、计漏检 PCK@.1、检测 recall、尾部 NME、
mask IoU、鼠体及全图深度 AbsRel；与各自原 5000 步结果比较。只看总平均或
框匹配 PCK 不足以判断双鼠改善。不跨分辨率直接比较绝对像素误差。
最后 5000 步训练曲线用于检查是否仍明显下降；不提前声称已充分收敛。
报告文件：`docs/experiments/pose_convergence_15000_results.json`（完成后生成）。

初步估计两组训练约 2 小时，另需 encoder 缓存、重载和视觉验收时间；不是完成保证。
启动前 37 项回归测试通过，新增测试覆盖旧恒定 LR 行为、边界、余弦中点、终点和单调性。
当前状态：协议与队列已实现，尚无本轮精度结论。

## 后续决策边界

若双鼠训练误差明显降低但验证仍差，优先检查泛化/实例检测，不直接增加像素；
若训练中仍出现框正确但骨架收缩，下一独立变量考虑实例相对坐标或 ROI 特征。
两者均是待验收后的决策，不由队列自动启动。单种子、共享合成资产限制仍然存在。
