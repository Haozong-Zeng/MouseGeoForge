# 纯几何底视适配失败分析

2026-10-18。范围：复核已完成的4,000更新，检查尺度、梯度和覆盖，提出下一轮方案。**没有启动训练，没有优化器更新，没有续训或自动冻结对照。** 原模型、优化器、EMA、RNG及实验协议不修改。

主判断：当前配方改善了部分深度，却没有让相机与深度一起形成可靠几何。主要证据指向几何heads的漂移、旋转输出的数值条件恶化、联合投影与监督目标冲突，以及很窄且混杂的rig训练覆盖；不能简单归结为encoder忘记预训练特征，也不能归结为一个毫米/米换算错误。

## 证据范围

- 主终点仍是原337相机包的最终EMA，raw作对照，见[最终路线与结果](bottom_geometry_experiment_roadmap_20261018.md)。诊断不替换预登记的晋升结果。
- 新增发布版/最终EMA各52包只读推理：全部24个新训练rig场景、全部6个未见rig场景、6个真实标注包和16个原合成动作留出包。后两者是小子集，不能与全验证集混写。未见rig的6场景及485/107转移点与原完整rig验证一致。
- 对相同28包做encoder/heads参数交叉替换。另在实际schedule第3/4/5更新的混合8样本上计算两端点梯度，不执行`optimizer.step()`。补采ClimbWall、CRIM13、Water等历史梯度记录漏掉的来源。
- 证据目录：`output/bottom_geometry_failure_analysis_20261018/`；汇总`analysis_summary.json`，原始推理`inference_*.json`，梯度`gradient_probe_*.json`，输出条件`camera_output_conditioning.json`，全程日志统计`logs_and_coverage.json`。汇总记录原始文件SHA256。本地分析入口：`tools/analyze_bottom_geometry_failure_20261018.py`，执行代码与完整输出不随此次文档发布。公开的[紧凑诊断证据](experiments/bottom_geometry_failure_diagnosis_20261018.json)包含模块替换、梯度、覆盖与条件数统计。

## 一、尺度记账一致，不代表学到的两输出一致

当前本地实现`tools/pure_geometry_bottom_20261018.py`对多视图合成使用同一完整rig基线，同时除相机平移和深度；真实标定统一完整七相机基线330.050mm，不随缺失相机子集变化。单视图回放没有基线，另用渲染深度中位数定尺度。因此没有发现本轮代码里直接把一种平移单位和另一种深度单位拼接的证据。不同来源的规范尺度仍不同，不能把它当可移植的真实毫米监督。

投影取决于`R、K、t/Z`。将同一预测的全部`t`和`Z`同时乘正数，不改变有效前向投影；旋转本身更不随尺度改变。52包中的几何真值夹具做共同乘2检查，投影差为0；有稠密支持的包，用真值相机/深度得到100% coverage32。相机编码会把主点固定在中心，但这批合成真值编码往返也全部达到100% coverage32，暂不支持“明显坐标换算错误是主要原因”；这不等于所有数据和亚像素约定都已获全面认证。

目前深度项约束GT规范尺度，camera项约束平移基线，但联合转移允许两者互相补偿。中心化shape只减去均值，没有除以尺度，因此不是尺度不变损失。单视图的深度规范又不同。结果可以是depth AbsRel明显改善，原来相互兼容的预测相机/深度却不再兼容。旧合成其他视角全验证中，已知相机＋预测深度覆盖从4.69%升到46.76%，预测相机＋预测深度却从55.03%降到29.81%，直接说明深度单项变好不能代替联合几何。

新增反事实诊断，全部为未见rig底视的固定485点：

| 最终EMA诊断 | coverage32 |
| --- | ---: |
| 原预测相机＋预测深度 | 2.06% |
| 预测相机＋GT深度 | 3.09% |
| 再用GT基线比校正预测相机平移的单一尺度 | 0.21% |
| GT相机＋预测深度 | 14.43% |
| GT相机＋对预测深度做GT辅助单尺度校正 | 18.76% |

校正没有救回底视，故**尺度失配存在，但不是全部原因**；剩余涉及旋转、平移方向、内参以及逐视图深度形状。基线比是在当前预测旋转下算的，旋转错误也会影响相对平移，不能把它当独立、精确的尺度估计。GT辅助校正只用于分解错误，不计入晋升、部署或关键点精度。

特别是rig07，最终底视深度/GT中位比在三个场景为1.193/1.336/1.246，存在系统高估；rig06约0.965/1.092/1.079。单一全局尺度偏置不能概括两套rig。训练24场景底视AbsRel从0.2284降到0.0674，旋转均值从148.45°降到57.95°，但同一批训练场景底视联合覆盖仍从8.48%变为6.00%。所以既有泛化差距，也有训练域本身未学成联合几何的问题，不能只称验证过拟合。

## 二、梯度失衡与冲突确实存在，但须分清发生在哪里

原校准只用前16个样本：camera12次、depth11次、shape9次、transfer8次、real_sparse4次；未覆盖Water，DANNCE仅1次。只测共享encoder，没有用heads的梯度定权，冻结权重为camera1.04、depth11.35、shape62.91、transfer2.21、real_sparse1.99。初始共享梯度的中位数相近，不保证训练后或head梯度仍相近。

全程4,000更新中**89.5%被clip10**，裁剪前范数中位41.4、P95 303.4、最大15,396.9。第1501–2500更新为99.8%，2501–4000为99.93%，比“全程89.5%”更严重。此前路线中把89.5%称为末次恢复段比例不准确，它是全程累计比例。

历史共享encoder梯度中：

| 来源 / 项目 | 观察 |
| --- | --- |
| 新rig：camera与transfer | 80样本中62.5%余弦<0，42.5%低于−0.3，中位−0.182 |
| 原底视：camera与transfer | 39个有效样本中53.8%<0，41.0%低于−0.3 |
| 新rig：camera与depth | 中位−0.0038，近乎正交，不支持普遍强烈的直接对冲 |
| 原底视：加权shape共享梯度 | 中位21.51，而camera4.34、depth1.06；shape高权重已不再平衡 |

固定每100更新诊断产生采样混叠：只测到MoSeq底视，漏掉ClimbWall底视；replay只测到两个Anipose来源，未测到CRIM13、Water及其他回放。上述“原底视”梯度不能推广至所有来源。

补做第3/4/5更新的完整混合梯度后，最终EMA聚合camera/transfer余弦分别+0.101/−0.262/−0.411；合成depth与真实sparse分别−0.325/−0.488/−0.071。跨来源冲突确实出现。不过camera与总梯度余弦仍为正（0.503/0.991/0.202），没有证据说每次总更新都在反向优化相机。余弦是欧氏梯度诊断，不等于带历史动量和预条件的AdamW实际更新归因。

全局裁剪不会消除同一步损失权重的相对作用，也不会让AdamW每步更新完全相同；当前每步已经混合8个来源，不能沿用旧batch1相机视频步的简化解释。但某一head的大梯度会让所有模块一起被缩小，仍值得处理。

## 三、额外查到旋转参数的数值条件恶化

camera head直接输出未约束范数的四元数；`quat_to_mat`使用`2/sum(q²)`，几何旋转对四元数正数缩放不变，回传条件数随范数减小而恶化。新测地线损失没有约束这个径向自由度。

在固定ClimbWall训练包中，发布版三相机范数约0.9993/0.9997/0.9148，最终EMA为0.1587/**0.00838**/0.3807。相同camera损失对输出四元数的梯度范数从1.92升到129.72；加权camera head梯度范数达到约1,166.6（除以8之前）。MoSeq另外两个包的加权shape对depth head梯度约589/972，共享encoder约17/33。

这是与频繁裁剪相符的具体病态，不只是“loss权重偏大”的猜测。不能仅凭一个输出包将全部尖峰归因于它，也不能把范数塌缩直接归因为weight decay。单独加`F.normalize`仍会经原始小范数反传，不能声称这样就解决条件数；后续需要明确的范数约束/稳定参数化、有限值检查和模块梯度监控。

## 四、其他视角退化主要随heads出现，不能只怪encoder

在完全相同的28包、相同支持上做参数交叉替换，真实其他视角为6包内的诊断小子集：

| Encoder / camera+depth heads | 真实其他视角旋转均值 | 原合成其他视角联合coverage32 |
| --- | ---: | ---: |
| 发布 / 发布 | 4.67° | 74.59% |
| 最终EMA / 最终EMA | 25.64° | 37.30% |
| 发布 / 最终EMA | 31.11° | 30.27% |
| 最终EMA / 发布 | 4.57° | 73.51% |

在该子集，换回发布heads基本恢复侧视性能，保留最终heads则即使换回发布encoder仍退化。可定位当前权重中的主要漂移位置在heads；不能据此断言冻结encoder重新训练一定得到同样结果，交叉替换可能存在模块适配交互，仍需真正配对训练。

真实sparse只经depth head和共享encoder反传，不直接更新camera head；这批真实数据又没有camera保留损失。因此“使用已知相机监督真实几何”并不会自动保住模型预测的其他相机。合成重放有GT相机监督也没有形成硬保留约束，尤其在任务尺度、模块梯度及参数条件数变化后。仅增加encoder冻结对照不能解决camera head漂移。

## 五、数据覆盖比采样次数窄得多

- 新rig8,000次曝光只来自**6套rig×4帧＝24场景**，每场景平均约333次，全是ClimbWall、同一鼠资产、40mm镜头。不是8,000个独立几何配置。
- 留出6场景同时改为WashFace、44mm镜头和未见rig；rig06底视水平偏移80，超过训练10–60范围；rig07底视倾角约27.55°，高于训练约2.79–25.64°。新rig子集未在训练中随机焦距，现验证不能把rig、动作和镜头变化的影响分开。
- DANNCE1只有一个额外真实rig，metadata将六相机方向标为`unknown_real_orientation`，尚不足以证明提供了经审计的底视监督。2,000次曝光也不是2,000套装置。
- 真实人工标签134组虽然曝光8,000次，九采集仍是一个固定rig。它能改善该已知装置的稀疏深度一致性，不能补齐未知装置相机监督。
- 9,000次replay中1,800次是单视图；两个Anipose来源没有body mask，因而没有body-shape/体表联合转移项。回放比例不等于有效多视角保留梯度比例，应按实际任务和可见点支持计量。

优先级是先处理数值条件和模块保留，再用因子清晰的比较检验解耦目标与encoder解冻，随后单独验证rig覆盖。当前顺序已由[Claude意见复核与尺度方案](bottom_geometry_v3_reconciled_plan_20261018.md)修订；[原四臂提案](bottom_geometry_paired_v3_proposal_20261018.md)保留为历史。该设计尚不具备完整数据manifest、固定系数和可执行训练器；当前授权仅分析与设计，不运行预热训练、渲染或任何实验臂。
