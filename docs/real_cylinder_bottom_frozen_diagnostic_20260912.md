# 真实 Cylinder Bottom view：冻结权重复测与下一步

日期：2026-09-12。结论：真实数据已经可用；当前主要矛盾不仅是底视域差异，还包括 **mask 与框/关键点定位脱节、底视几何估计失效、跨视角上下文不稳定**。先验证定位机制，不优先增加训练步数。未训练、未替换生产模型，未访问锁定留出序列。

## 本轮协议

- 开发序列 AZL3（780、796、811）、CR2/FR2（各 0、780、1559），共 9 个时间点。AZL3 三帧相邻，不能当作三个独立姿态；本轮只做小规模故障定位，不能代表所有 Cylinder 视频。
- A 为底视，D/E 为侧视。比较 A、D、D+A、D+E、D+E+A、A+D+E 六种输入：54 次共享 encoder 前向，两套任务头共 216 条视图结果。
- `base768`：`output/pose_diverse_core23_768_v1/seed17_off/final_heads.pt`；`cylinder800`：`output/cylinder_adaptive_temperature_v1/adaptive_temperature/final_heads.pt`。两者共用原版 `vggt-omega/vggt_omega_1b_512.pt` encoder/camera head。它们的训练历史不同，**不是温度机制的严格消融**。
- 原始 RGB 解码，遵循用户“暂按未矫正处理”的约定，仅一次原 K/D 畸变矫正。1080×1200 原图缩放至 691×768，左右补 6/7 像素，网络输入 W×H=704×768。记录 OpenCV 半像素中心变换；不强拉伸成方形。
- 已知标定只用于比较相对旋转，未输入 encoder。世界坐标、同步和玻璃折射仍需独立核验；普通镜头去畸变不等于去除折射。
- 最高 objectness query 用于展示；阈值 0.5。关键点分析使用 16 个非尾巴点（0–6、14–22），不表示模型没有输出尾巴。
- 不使用人工标签训练或排名。DLC、现有分割和视觉体积深度都是预测/伪标签；不报告 PCK、MPJPE 或真实分割准确率。

完整机器记录在 `output/real_cylinder_bottom_frozen_v1/`：`protocol.json`、`summary.json`、`per_view.json`、`context_changes.json`、`translation_probe.json` 和逐条件预测快照。主实验前后核验 encoder/任务头文件哈希不变。

## 观察与证据

### 1. 能跟随鼠体的 mask，不能保证定位头跟随鼠体

人工视觉检查了全部 9 张底视分支对照图：每张只有一只小鼠；最高分 query 的 mask 大体跟随鼠体，但框和身体关键点常偏向画面中央、尾部或远离实际身体。FR2 尤其明显。侧视也存在定位问题，因此不能全部归因于 Bottom view。

三帧 AZL3 另外做向右平移 64 网络像素的冻结测试。以“平移前预测 mask 平移后的形状”匹配 query，未使用真值：

| 指标（两模型、三帧） | 结果 | 含义 |
| --- | --- | --- |
| 平移前后预测 mask 的等变 IoU | 0.990–0.993 | 分割分支几乎同步移动 |
| 框中心水平位移 | 0.3–7.5 px | 远小于应有的 64 px |
| 身体点平均水平位移 | −0.5–29.0 px | 关键点也没有充分跟随 |
| 身体点相对预期平移的平均残差 | 35.9–65.1 px | 不是微小定位抖动 |

这支持“定位分支过度依赖位置先验/没有充分绑定局部图像证据”的判断，但不是单一架构因素的因果证明：平移也改变了边界和上下文。需要进一步平移、缩放和裁剪对照，而不是直接归咎于某层 encoder。

### 2. 错误预测仍高度自信，单鼠出现多槽响应

单底视的两套模型均在 9/9 图像中输出多个 objectness≥0.5 的槽，最高分均值分别为 0.99980、0.99955。更高置信度阈值不是可靠解法。加入侧视会减少部分重复响应，但没有人工关键点真值，不能据此宣称精度提升。

不能把输出数量固定为 1：项目目标仍是单鼠到多鼠。重复抑制、定位质量评分与真正的多实例定位应分别验证；本轮单鼠真实视频不构成双鼠分离验证。

### 3. 原版相机头的底视相对旋转严重不符

以下均为 9 组相对旋转与提供标定的平均角度差；是相机几何诊断，不是关键点误差：

| 输入与比较 | 平均角度差 |
| --- | ---: |
| D+E，D→E | 2.90° |
| D+A，D→A | 135.93° |
| D+E+A，D→E | 4.47° |
| D+E+A，D→A | 138.76° |
| A+D+E，A→D / A→E | 121.35° / 118.08° |

侧侧基本符合、侧底严重偏离，说明底视相关的几何输出当前不可直接用于可靠重建。但应继续用独立重投影检查排除底相机坐标约定/标定问题；不能只凭这一指标断言其预训练完全没有底视。

### 4. 相同图像更改视图组合或顺序，关键点明显漂移

| 同一图像的条件变化 | base768 身体点平均位移 | cylinder800 |
| --- | ---: | ---: |
| A → D+A，观察 A | 85.1 px | 38.6 px |
| A → D+E+A，观察 A | 89.0 px | 49.2 px |
| D+E → D+E+A，观察 D | 27.5 px | 29.9 px |
| D+E+A → A+D+E，观察 A | 38.4 px | 35.8 px |
| D+E+A → A+D+E，观察 D | 38.5 px | 34.6 px |

这是最高分槽的上下文敏感性，槽可能切换，不是准确率。参考视图在此类架构里本来就可能有特殊地位，不能把顺序敏感性直接称为实现 bug；但对固定相机、灵活 1–N 视图应用仍是需要控制的任务输出不稳定性。

### 5. 深度只能暂作辅助诊断

AZL3 底视的原版预训练深度与当前统一视觉体积伪深度，在侵蚀后的前景内 Spearman 约 −0.43 到 0.23，随组合改变；训练后深度也没有显示稳定的一致关系。不能解释成“真实深度必然反了”：视觉体积对腹部、足、尾和接触面的形状本来就存在系统偏差，且此处支持区域仍包含尾巴。

可视化深度按各图分位数独立着色，仅展示相对结构，不作毫米级误差、跨视图颜色或尺度比较。不要用同一套生成 mask 的伪重建评价模型后，再把高一致性当作真实几何准确率。

## 优先改进顺序（尚未实施）

1. **先做现有 mask 参考框候选的真实冻结 ON/OFF。** 复用 `docs/mask_box_candidate_usage.md` 中 seed17 对应候选和严格配对/哈希守卫。它已在合成数据验证，但尚无真实 Cylinder 结论，且本轮 704×768 输入需先做形状预检。候选只改框，不会修复关键点；也不能用新框改变实例匹配后就宣称关键点提升。尾巴、噪点对 mask 外接框的干扰须沿用主连通域与残差约束。
2. **把关键点解码绑定到实例的局部图像证据。** 推荐最小实验是实例参考位置/ROI 条件化的粗定位，再在局部特征上细化身体关键点；配合位置多样化合成样本及平移/缩放增强。不能仅按新框机械平移旧关键点，也不能要求所有遮挡点必须落入可见 mask。先验证等变性、实例对应和原侧视不退化，再增加训练量。
3. **已标定固定相机优先使用已知 K/E，拆开单视图识别与多视图融合。** 对照独立单视图特征/预测 + 标定约束的后期融合，与现有联合编码；给底视几何或关键点证据质量建立门控，避免破坏可靠侧视。仅替换输出相机不会自动修复联合 attention。维持真实 1–N 视图输入，单视图无需复制假视图；遮挡点可预测，但融合权重应区分可见证据、定位质量与几何一致性。
4. **后做质量置信度和时序。** objectness 不能代替定位可靠性；先校准/学习定位质量，再做实例关联。固定相机时序可以缓解随机抖动，却不能纠正稳定的位置偏差，不应首先用平滑掩盖它。
5. **标注回来后再决定扩量与选型。** 按独立视频源划分开发/留出，分别统计底视和侧视、可见/遮挡的关键点误差、实例数/框召回、mask 边界及多视图重投影/3D；没有可靠 3D 真值时，重投影一致性仍不能替代真实 3D 准确率。GR2/UR2/UR3 继续锁定。真实开发数据一旦被用于选架构，不能再称为独立最终测试集。

外部设计参考而非本机效果证明：VGGT 官方实现支持一张到多张输入；Depth Anything 3 官方接口支持已知内外参，其相机条件化设计可供固定相机融合参考。未在本轮下载或运行 DA3，不能据此宣称替换 encoder 即可解决底视。
