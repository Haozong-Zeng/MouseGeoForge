# 纯几何底视适配 v2 失败诊断与 v3 配对实验方案（2026-10-18）

依据：`output/pure_geometry_bottom_20261018_v2/` 的 `geometry_seed17/train.jsonl`（4000 更新，每 100 更新的分项梯度）、`release_baseline.json`、`ema_final_step004000.json`、`schedule.json`、`render_config.json`，以及训练器 `tools/pure_geometry_bottom_20261018.py`。只读分析，未启动训练。v2 的结果与门槛保持原样。

## 一、诊断结论

v2 的主要失败不是训练步数或 batch，而是三件事叠加：**目标量纲（gauge）与 VGGT 原生量纲不一致、相机与深度失去共同尺度、未见装置覆盖过窄**。其他视角退化则是因为真实装置的相机输出失去了锚定。

### 1. 尺度耦合：训练主要在学一个尺度常数，并破坏了相机–深度自洽

v2 用“完整 rig 中位基线 = 1”作为量纲：深度损失是绝对 log 深度，相机损失含绝对平移、相对平移的 log 尺度项。VGGT 发布模型的输出处在它自己的量纲里（按场景点距离归一化）。证据：

| 动作留出（训练 rig，其他视角） | 发布模型 | 最终 EMA |
|---|---:|---:|
| 预测相机＋预测深度转移 coverage32 | **55.0%** | 29.8% |
| 已知相机＋预测深度转移 coverage32 | **4.7%** | 46.8% |
| body AbsRel | 0.283 | 0.056 |
| 中心化形状 RMSE | 0.058 | 0.048 |

- 发布模型在自己的量纲里相机与深度是自洽的（预测相机转移 55%），只是绝对尺度与基线量纲不符（已知相机转移仅 4.7%）。
- 训练后深度被拉到基线量纲（AbsRel 0.28→0.06，已知相机转移 4.7%→47%），但预测相机没有同步变化，**自洽性被打破**（55%→30%）。中心化形状只从 0.058 改善到 0.048，说明深度“形状”变化很小，主要变化是绝对尺度。
- 已知真实装置的人工射线重投影（底视 6.6%→39%，其他 5.6%→54%）同样可能大部分来自“学会这台装置的一个尺度常数”。在做尺度对齐的诊断之前，不能把它当作几何质量改善。
- 基线量纲在单视角或底视主导的视角包里**不可观测**：同一张底视图像，在相机离地 140 或 240 的装置里对应完全不同的“深度/基线”比值。模型只能记住训练装置的比值，所以未见装置上 body AbsRel 反而从 0.142 升到 0.169，已知相机转移从 30.7% 降到 14.4%。
- 另外有 1,800 个单视角微批（5.6%）改用“渲染深度中位数 = 1”的量纲，与多视角包的基线量纲互相矛盾：同一网络输出被两套绝对尺度监督。

### 2. 梯度冲突：相机项在晚期主导被裁剪的更新

每 100 更新记录的加权梯度范数（中位数）与同一样本内的余弦：

| 来源 | 阶段 | camera | depth | shape | transfer | cos(camera, transfer) |
|---|---|---:|---:|---:|---:|---:|
| 新 rig | 早（≤1000） | 1.33 | 0.60 | 0.74 | 0.96 | −0.05 |
| 新 rig | 晚（>2500） | **4.72** | 0.21 | 0.24 | 1.15 | **−0.40** |
| 既有底视 | 早 | 1.18 | 3.96 | **51.2** | 2.04 | −0.13 |
| 既有底视 | 晚 | **9.30** | 0.70 | 12.3 | 0.78 | +0.41 |
| DANNCE | 早 → 晚 | 0.94 → 2.0 | | | | |
| 回放 | 早 → 晚 | 0.48 → 1.81 | 0.45 → 0.11 | | | |

- 相机损失中位数从 1.01 降到 0.41，但它的梯度范数在所有来源里都增长了 2–8 倍；总梯度范数从约 27 升到 47–66，裁剪比例在 2000 更新后回升到 81–89%。裁剪后的更新方向主要由相机项决定。
- 新 rig 上相机项与转移项的余弦到晚期是 −0.40：相机损失要求平移符合基线量纲，转移损失（对整体尺度不变）要求相机与预测深度同尺度，两者直接对抗——这正是第 1 点尺度耦合在梯度上的表现。
- 权重只在第 0 步用 16 个微批校准一次后固定。shape 权重 62.9 使它早期在底视上主导（加权 51），晚期相机梯度变大后，权重又失去平衡。
- 记录的余弦只覆盖“同一样本内的任务对”。跨来源冲突（真实稀疏重投影 vs 合成相机 vs 回放）没有测量，而其他视角退化恰恰可能来自跨来源冲突。

### 3. 数据覆盖：未见装置在训练分布之外，评价样本也太少

- 训练只有 **6 套随机 rig × 1 个动作（ClimbWall）× 4 帧 = 24 个场景**，32,000 个微批里有 8,000 个来自它们，每个场景约被重复 333 次。
- 所有训练 rig 镜头都是 40mm，两套留出 rig 都是 **44mm**，焦距在训练范围之外。val_rig06 底视水平偏移半径约 80，训练 rig 最大约 60，也是外推。留出动作 WashFace 与训练动作不同，装置变化与动作变化混在一起。
- “既有底视”池（4,000 微批）只有 MoSeq 和 ClimbWall 两组，并且共用训练装置，动作留出底视的改善（旋转中位数 80°→54°）很可能是装置记忆。
- 未见装置门槛只有 **2 套 rig、6 个底视相机对**，P95 就是 6 个数里的最大值。两套 rig 方向相反（rig06 旋转 89.6°→128.8° 而深度改善，rig07 旋转改善而深度变差），任何结论的统计功效都很低。

### 4. 其他视角退化的直接原因：真实装置相机失去锚定

- 真实人工标注包只计算 `real_sparse`（用已知 K/E 投影预测深度），**不计算任何相机损失**（`terms()` 里 `if rec['kind']!='real_labeled'`）；原始视频相机步又被设为 0%。所以训练中没有任何项约束真实装置的相机输出。
- 共享的最后两层被合成相机与深度量纲变化不断改写，真实其他视角预测旋转随之漂移：均值 7.7°→26.2°（AZR2L2 3.9°→17.9°，FR2 11.5°→34.0°，FR3 6.9°→25.3°）。
- 回放数据虽有相机损失，但它同样处在被改写的基线量纲里，CRIM13 其他视角联合转移仍从 89% 降到 45%：说明退化来自量纲迁移，而不只是缺少数据。
- 没有任何“保持发布模型行为”的约束（蒸馏、L2-SP 等）。

## 二、v3 设计改动

所有改动在两臂中同时应用；不放宽 v2 门槛，不回填。

1. **量纲：相机与深度共用一个逐包尺度。** 每个训练包用 GT（或已知标定＋渲染深度）计算一个尺度 s*，把预测深度与预测相机平移**同时**除以同一个由预测估计的尺度（如有效像素预测深度的中位数），再与同样归一化的目标比较。深度用尺度不变 log 损失；平移只比较方向和相对比例；删除绝对平移项和单独的 log 尺度项。单视角包与多视角包用同一规则，消除两套绝对尺度。
2. **保持项：发布模型蒸馏。** 对所有非底视视角（以及回放、DANNCE、真实包），在发布模型自己的量纲里，蒸馏它的相对相机位姿和尺度对齐后的深度。只对底视相关的量放开。另外给真实人工标注包加相机损失（已知 K/E）——对已标定装置来说记住它正是部署需要的；它只作为锚定，不计入泛化证据。
3. **数据：装置数量和参数范围优先于重复次数。**
   - 训练 rig 增至至少 48 套，每套 2 帧，每个场景访问次数降到约 10–40 次。
   - 参数范围要覆盖：镜头 30–55mm、底视高度、水平偏移半径 0–100、底视俯仰/滚转扰动、侧视方位和高度。
   - 动作至少 3 组（ClimbWall、MoSeq、另一组训练动作），渲染时动作与装置随机交叉，避免装置与动作同时变化。
   - 开发 rig 至少 12 套，按参数分成“范围内插”和“范围外推”两层分别报告，给出至少 36 个底视相机对。另设 8 套 rig 作为密封确认集，只在最终配对结束后评一次。val_rig06/07 已被看过，降为开发诊断。
4. **梯度：持续监测并分来源记录。**
   - 每 250 更新用当时的梯度中位数重新校准任务权重（限幅 [0.1, 10]，并记录变化）。
   - 另外记录跨来源余弦：把一次累积更新按来源（新 rig／既有底视／回放／真实／DANNCE／蒸馏）分组求共享参数梯度，记录两两余弦和范数。
   - 裁剪阈值改为按前 100 更新总范数 P90 设定，目标裁剪比例低于 20%。
5. **评价补充：尺度对齐诊断。** 对已知装置的稀疏重投影、已知相机转移，同时报告未对齐和逐包最佳尺度对齐两个版本，用来区分“学会了一个尺度常数”和“几何形状确实变好”。另加一个零训练基线：发布模型深度＋已知 K/E＋逐包尺度对齐。如果这个基线已经接近训练后结果，已标定装置就不需要编码器适配。

## 三、配对实验方案

### 阶段 A：配方筛选（单种子，只用开发集决策）

三臂同一发布起点、seed17、同一 v3 数据池和 8 微批顺序、1,500 更新、warmup 300 + 余弦、EMA 主评价。三臂都解冻最后两层，只改变目标：

| 臂 | 目标 | 要回答的问题 |
|---|---|---|
| A0 | v2 损失（基线量纲、绝对项），v3 数据 | 只扩数据能否修复未见装置 |
| A1 | A0 改为共用逐包尺度（设计改动 1） | 尺度耦合是不是主因 |
| A2 | A1 + 发布模型蒸馏 + 真实相机锚定（设计改动 2） | 能否同时消除其他视角退化 |

阶段 A 的决策规则在训练前登记：在开发 rig 上比较底视旋转中位数和 P95、预测相机＋深度转移 coverage32、其他视角保留（相机旋转和联合转移相对发布模型不劣于 1pp 或 5%）。只把胜出配方带进阶段 B；若三臂都没有改善未见装置底视位姿，就停止编码器适配，转向“已标定装置使用已知标定＋尺度对齐”的部署路线，不再加训练步数。

单臂约 1 小时（v2 的 4,000 更新约 2.7 小时，按比例估算），三臂合计约 3–3.5 小时，另需渲染新 rig 的时间。

### 阶段 B：正式配对 G0/G1

用阶段 A 胜出的配方：

| 臂 | 可训练参数 |
|---|---|
| G0 | 冻结编码器，只训练 camera/depth head |
| G1 | 另外解冻最后两个 frame/inter-frame block |

- seed 17、29、43，每臂 4,000 更新，同数据顺序、同初始化、同 EMA。共 6 次训练，单卡约 16 小时；可以先跑 seed17 的两臂（约 5.5 小时），再决定是否跑另外两个种子。
- 主终点：开发 rig 上的底视旋转中位数和 P95、平移方向 P95、预测相机＋深度转移 coverage32；其他视角保留；已知装置尺度对齐诊断。沿用 v2 门槛（旋转中位数和 P95 各降低 ≥30%，绝对 P95 ≤10°，方向 P95 ≤15°，联合转移 +5pp）。
- 只有 G1 在三个种子上都优于 G0、且保留条件成立，才说明需要编码器适配；全部门槛满足后，才在 8 套密封确认 rig 上评一次。
- 几何通过前不训练 2D head，也不启动 3D 关键点。

### 必须先完成的准备

1. 渲染新 rig 集（训练至少 48 套、开发 12 套、密封 8 套），程序 QA 和代表图检查沿用 v2 流程。
2. 训练器 v3：共用尺度的损失、蒸馏项、真实相机锚定、周期性权重重校准、跨来源梯度记录，并补 CPU 夹具（尺度不变性：同时缩放深度和平移时损失不变；单视角与多视角量纲一致）。
3. 评价器 v3：尺度对齐诊断、内插/外推分层、零训练已知标定基线。

以上都需要用户授权后才执行。
