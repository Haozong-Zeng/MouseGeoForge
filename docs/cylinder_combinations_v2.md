# Cylinder 相机组合覆盖 V2（2026-09-10）

## 目的与边界

继 V1 物理视角均衡和 pose-head-only 对照后，优先修正采样，不增加训练量。
旧 V1 用姿态索引生成相机组合：每个姿态的单视图只有顶/底之一，双视图全程
没有 `[2,6]`，三视图始终是侧＋底＋顶。姿态、相机子集和参考相机产生了绑定。
这可以解释部分风险，但不能直接认定是全部误差的原因。

本轮只使用本地合成 Cylinder，不包含真实 Cylinder。开发集仍是同资产、同相机
布局的 WashFace；动作来源与 ClimbWall 训练分离，但不构成独立真实域测试。

## 锁定对照

- 基线：`output/cylinder_view_balance_v1/balanced_views` 已完成结果，不重复训练。
- 新候选：`output/cylinder_combinations_v2/combination_coverage`。
- 原始初始化相同，不接着上一候选权重训练；seed 17、lr 3e-6、800 步、768 长边。
- 冻结 encoder；更新 shared adapter、depth head、instance pose head，与 V1 一致。
- 每一步的源姿态、图像尺寸、视图数量、学习率和总预算不变；400 步原始回放不变。
- 耦合关闭，尾巴监督和时序设置不变；同一场景始终使用原始相机对的归一化尺度。
- 每轮 1,800 张图像、3,540,384 patch tokens；复用相同 88 个开发记录、17 项验收门槛。
- 最终步保存；不按开发集挑 checkpoint，不自动替换现用模型。

768 是网络输入尺寸；ClimbWall/WashFace 原图仍为 512×512，上采样不会增加细节。

## 新采样规则

`mousegeoforge/cylinder_combinations.py` 从标定外参识别的角色映射生成组合，
不依赖固定相机编号，也不读取开发集来挑组合。

| 视图数 | 策略 | 全局覆盖要求 |
|---|---|---|
| 1 | 每个姿态独立交替顶/底，初始方向随机 | 16 个姿态都见过顶和底 |
| 2 | 所有侧—顶/底组合及正反顺序，耗尽一轮再重复 | 12 种无序、24 种有序对 |
| 3 | 34 次侧底顶、33 次两侧底、33 次两侧顶 | 36 种含顶或底的无序组合 |
| 4 | 50 次两侧底顶、25 次三侧底、25 次三侧顶 | 55 种含顶或底的无序组合 |

组合池内优先减少同姿态的重复，三/四视图的首相机另按访问计数分配，其余顺序
打乱。每个相机都必须在 V=2/3/4 当过首相机。单视图没有新增侧视分支，侧视监督
保留在原始回放中。有限预算只保证全局组合覆盖，**不保证每姿态覆盖所有组合**，
也不保证三/四视图的全部排列。

这轮同时改变了子集多样性、顺序和物理角色频率，因此是“采样策略整体对照”，
不是只隔离顺序影响的实验。物理角色计数保存在 `coverage.json`，不可忽略它来
宣称单一因果关系。

实际 Cylinder 400 步中的 1,000 张图像：旧采样顶/底/侧 = 292/308/400，
新采样 = 241/243/516；另外 800 张回放图像完全不变。

```bash
PYTHONPATH=vggt-omega:. .venv-vggt-omega-eval/bin/python tools/train_cylinder_combinations_v2.py --prepare-only
PYTHONPATH=vggt-omega:. .venv-vggt-omega-eval/bin/python tools/train_cylinder_combinations_v2.py --launch
PYTHONPATH=vggt-omega:. .venv-vggt-omega-eval/bin/python tools/verify_cylinder_combinations_v2.py
PYTHONPATH=vggt-omega:. .venv-vggt-omega-eval/bin/python tools/analyze_cylinder_combinations_v2.py
```

配置从已验证 V1 协议派生，并完整写入新 `protocol.json`；旧数据、代码和权重
哈希须一致。运行器拒绝覆盖已完成实验。首次预检发现报告键的 JSON 类型不一致，
启动保护在模型训练前中止；日志完整保留于
`output/cylinder_combinations_v2_preflight_failed`。修复后加入 JSON 往返一致性测试，
重新预检通过才启动，不复用失败预检协议。

验收检查包含同初始化指标一致性、逐步源数据/预算、原始回放、全组合覆盖、
标定投影、跨子集世界尺度、checkpoint 重载、有限 loss 和冻结 encoder。
视觉对照固定使用 V1 原始模型最困难的底视帧 55，不依据候选结果挑图。

## 结果

已完成，训练与两次评估总计 371.8 秒。运行验证通过，17 项性能门槛通过 10 项，
仍未达标，**不替换现用模型**。旧采样也是 10/17，但通过/失败项目并不完全相同。

### 底视身体关键点（16 点，不含尾巴；NME 越低越好）

| 开发设置 | 原始模型 | 旧采样 800 步 | 新采样 800 步 | 相比旧采样下降 |
|---|---:|---:|---:|---:|
| 仅底视 | 0.29796 | 0.19012 | 0.18127 | 4.7% |
| 侧＋底 | 0.15761 | 0.20564 | 0.18864 | 8.3% |
| 两侧＋底 | 0.14112 | 0.20018 | 0.18011 | 10.0% |
| 两侧＋底＋顶 | 0.14091 | 0.19256 | 0.17250 | 10.4% |

三种多视图设置各 8 个姿态全部相对旧采样改善；仅底视为 6/8 改善。但新模型
的多视图底视 NME 仍比原始模型高约 20–28%，不能称为修好了多视图融合。

原始侧视相机对 PCK：0.49728 → 旧 0.45380 → 新 0.47690，回到原保留门槛内。
原始双鼠相机对 PCK：0.53601 → 旧 0.48438 → 新 0.49049，仍低于 0.50601 门槛；
新双鼠 Core23 NME 0.12936（门槛 0.12806），深度 AbsRel 0.02469（门槛 0.02373），
两者也没有通过。多视图顶视身体 NME 仍退化。

底视深度相对原始模型改善，但比旧采样略差：仅底视新 AbsRel 0.06582，
侧底 0.05347、两侧底 0.06781、四视图 0.06806。组合多样性和侧视占比变化存在
深度/关键点权衡，不能只报告关键点获益。

### 覆盖、几何与视觉检查

- 每姿态遇到 19–23 种相机顺序，旧版只有 4 种。
- 开发 `[2,6]` 在训练中完整出现 4 次；`[2,0,6]` 和 `[2,0,7]` 各 1 次。
- 四视图开发 `[2,0,6,7]` 的无序子集出现 3 次，同首相机出现 1 次，完整排列
  没有出现。因此四视图结果包含排列泛化；不可说开发全部排列都见过。
- `side_only=[2]` 单视图没有在 Cylinder 新增训练槽中出现，不能以此声称所有
  1–4 视图组合都被训练覆盖。
- 初始化的 88 条开发记录相对 V1 指标最大差异 0；GT 标定重投影最大误差
  0.000246 px；跨子集 K/E 和世界尺度一致；400 回放槽完整保留。
- checkpoint 重载、源数据/代码/权重哈希、逐步图像和 token 预算验证通过。
  122 项单元测试通过。失败预检没有进行梯度更新。
- 已实际查看 `comparison.png`、`pair_coverage.png`、`training_curves.png` 和
  `hardest_bottom_pose.png`。固定帧 55 的双/三视图底视 NME 从 0.146/0.144
  降至 0.133/0.125，但头部点仍偏到身体右上方，部分四肢点向一侧偏移。
  该帧单底视 0.173 → 0.174 略差，不能用一帧替代全体指标。

3D 仍仅作为有已知 K/E、GT box 辅助匹配的诊断，不能当作端到端能力证明。
侧底、两侧底、四视图的新三角化身体点覆盖率分别为 20.3%、71.1%、93.8%；
条件误差分别为 16.34、18.33、20.04 原生场景单位。支持点集合不同，不能只
比较条件误差的数值，也不能将这些单位直接标成毫米。

## 下一步判断

保留新采样规则作为后续候选的基础，但暂不扩大长训练或提升网络输入尺寸。
本轮证明修正采样在这个单 seed 合成开发集上有帮助，不能证明剩余问题只是
训练量不足，亦不能确定冻结 encoder 是唯一原因。

下一项优先做**关键点定位分解审计**：分别导出粗坐标和局部热图修正后的坐标，
统计头部/四肢误差、GT 是否落在局部搜索窗内，以及误差与可见性的关系。
现有头已有局部热图分支，当前 pilot 的显式 local-heatmap loss 权重为 0；
不能把它误称为“没有局部头”。先区分粗定位越窗、窗内特征定位错误和跨视图
输入扰动，再决定局部监督、扩大搜索窗或视角条件残差中的单因素对照。
任何后续候选仍需保留原始双鼠/侧视的验收门槛，而非仅针对底视优化。

后续分解审计已完成，见 [粗定位与局部热图分解](cylinder_localization_audit_v1.md)：
存在粗定位越窗和分散热图两项限制；统一增大温度会损伤双鼠表现，下一项优先
比较直接粗坐标辅助监督，而非继续增加训练量。
