# 当前实验思路与 H100 数据规模规划

更新：2026-10-18（America/Los_Angeles）。本页补充当前[底视几何路线](bottom_geometry_experiment_roadmap_20261018.md)和[H100 计划](h100_multiview_validation_agent_plan_20261016.md)，是数据规模、外部数据和后续比较的最新规划入口。本文更新不启动训练或集群，不恢复已暂停自动化；已有实验结果和登记门槛不变。

## 决策摘要

1. **本机用来验证实现和关键假设，H100 多卡用来充分覆盖数据并验证泛化。** 不再把少数同步帧反复训练后的失败解释成整个方法无效，也不把训练误差下降解释成泛化收益。
2. **H100 阶段以全部已准入训练数据为主实验规模。** 小子集用于程序预检和学习曲线，不能成为整次集群实验的默认训练池。“全部”指训练分区内可合法使用、语义及质量符合相应任务要求的数据；开发、封存测试和不合格数据始终不进入训练。
3. **先减少数据覆盖不足和几何目标不一致，再增加训练预算。** 相机、深度共用尺度，底视/其他视角保留、独立 rig 和动作覆盖需分别检查；多卡与大 batch 本身不解决过拟合。
4. **PanoMouse 优先用于经语义审计的 2D 空间热图验证；OSF 优先补齐标定与独立物体验证。** 发布鼠体 3D 的重投影一致性、标定板拟合误差、自动关键点精度和物理 3D 精度分别报告。
5. 当前两条路线独立回答问题：已标定装置使用已知 K/E；未知装置才需要验证预测相机泛化。冻结发布版编码器的外部 2D 基线可单独开展，不以它替代失败几何模型的验收或晋升。

| 证据 | 能支持的结论 | 不能支持的结论 |

## 数据规模与分区

首先按动物（可获得时）、采集、装置、动作来源建立准入清单；每项包含来源、版本/hash、使用许可、标签语义、相机约定、历史模型曝光和训练/开发/封存角色。相同同步时刻的全部相机及相邻视频片段保持在同一角色；同源动作和近重复图单独审计。

每个来源分别报告：动物数、独立采集数、独立装置数、动作/场景数、同步时刻数、视图数、有效人工点数、伪标签点数、无标签帧数、未知/拒绝数。数量未知写未知，不按 session 推定不同动物，不按文件夹推定不同装置。

| 数据池 | 当前状态 | 计划用途 |
| --- | --- | --- |
| 当前修订人工数据和已准入历史训练池 | 遵守各自分区与曝光登记；历史 CAL 为重复开发数据 | 保留基线与本域监督；不得把历史测试换成训练以扩大数字 |
| PanoMouse | 7,339 张图，7,293 张有标注和相机，323 个同步时刻、11 session；224 视频；尚未训练准入 | 先审计原语义和标记，再使用所有合格训练 session 的相应监督；无标签视频另建训练池 |
| OSF 四相机 | 原录像与模型已下载；动物关键点未发布；物理尺寸、标定验收和原始数据许可待合作者补充 | 原始底视外观与几何验证候选；不当作现成的 2D/3D 人工监督 |
| DANNCE、SBeA、Orbbec 等其他来源 | 盘点和任务适配逐项准入，不按名称默认可训练 | 扩真实采集/装置/动作覆盖；没有对应标签的样本不消耗定位监督更新 |
| 合成训练池 | 使用可追踪动作来源、相机与可见性真值 | 大量交叉 rig、动作、外观和遮挡；另留新 rig、动作及独立组合 |

GR2/UR2/UR3 已有一次冻结测试曝光，不能再用于选方法；DANNCE2 和受保护合成 TEST 保持既有保护。若将来要用开发数据训练最终部署模型，必须在方案冻结后另留新的独立测试，并标明原开发分数不能继续作为独立验收。

大量视频应按采集和时间分层遍历，控制相邻帧冗余；全部训练数据的合法可用范围与每个预算内实际消费范围分别披露。优先增加独立覆盖，而非用同一装置的百万近邻帧淹没小来源。内部伪标签仅来自训练分区，记录教师版本与筛选通过/拒绝量，未知点不作负例。

## PanoMouse：可用部分和边界

[官方发布](https://huggingface.co/datasets/MouseTotalCapture/PanoMouse)声明 CC-BY-NC-4.0、24 相机和同步视频。实际样例已确认透明平台下的腹部、掌面/足底；但相机型号、快门类型、硬/软同步机制和实测时间偏差尚未核实。下载视频容器均为约 59.94 fps，同 session 已有视频帧数一致；这不证明曝光同步。标注图为 2704×2028，视频为 1352×1014，K 和坐标必须应用同一像素中心变换。

`calib_data.pkl` 与 JSON 的 11 session、243 组 K/R/T 条目及数值完全一致，没有额外畸变参数、标定板角点或拟合误差报告。不能把鼠体标注重投影误差写成 calibration RMS。

本地对全部 323 时刻的统计如下，均为 **2704×2028 原图像素**；平均数/中位数对可计算观测统计，未裁掉大误差点。缺失单列，不当作零误差。

| 一致性检查 | 中位数 px | 平均数 px | 缺失 / 已知观测 |
| --- | ---: | ---: | ---: |
| 发布 3D → 2D，全 92 点 | 9.48 | 12.95 | 451 / 285,802 |
| 发布 3D → 2D，身体 24 点 | 13.33 | 17.79 | 16 / 100,782 |
| 发布 3D → 2D，手/脚跟/足部六点 | 10.06 | 12.39 | 11 / 23,525 |
| 底部相机，上述六点 | 11.94 | 14.03 | 2 / 12,174 |
| 留一相机 DLT 重建，身体 24 点 | 15.87 | 20.07 | 106 / 100,782 |
| 固定 12 原图 px 共识方法留一相机，身体 24 点 | 16.66 | 22.04 | 3,807 / 100,782 |

典型误差说明数据值得利用，不应只因 P95 尾部就否定整体 2D 价值；当前固定共识方法则没有改善上述统计。发布 3D 可能由同批 2D 构造，不能视作独立物理真值，也不能据此分离标注、同步、标定误差。

2D 起步保留原始 92 点及分部有效标记，尤其区分 hand、heel、foot、趾点和本项目爪中心。若只比较共同语义，先审计和冻结对应表；不能直接重命名、混合冲突标签。官方 train/test 跨全部 session，本项目需按用途另登记采集留出；动物独立性、上游预训练曝光仍未知。46 张无相机/无标注的补充图保持单独角色。

## 下一步比较顺序

1. **数据和零训练诊断。** 核实 PanoMouse 语义、可见性和同步；向 OSF 合作者索取实测板格/物体尺寸、录像对应的完整 K/D/R/T、角点/物体点、同步及使用许可。已有发布模型用已知 K/E、明确可用尺度的零训练基线；需要目标 GT 拟合尺度的版本只列 oracle 诊断，不冒充可部署方法。
2. **已标定装置路线。** 使用已知标定，分别检验预测深度形状、可部署尺度处理和固定候选/身份读出。冻结发布版编码器的外部 2D 空间热图基线作为独立任务，先确认有效监督和 head 收敛，不要求它先证明未知相机估计能力；它不能使 v2 失败几何 checkpoint 获得晋升。
3. **未知装置几何路线。** 多视角相机/深度共用尺度规范；先验证不变性、数值/梯度和非底视保留。装置与动作交叉采样，训练范围内插和外推分层评价，旧 rig06/07 属已看过开发。配对比较冻结 encoder 几何 head 与部分解冻，数据/初值/曝光一致。不能用新数据、新损失和新 encoder 同时变化的差值归因为某一项。
4. **定位和 3D。** 通过几何的适配模型先冻结 encoder 训练空间 head 至预定收敛，再从同一 head 分叉比较冻结/解冻；自动 3D 仅在相应几何和 2D 定位都得到支持后推进。时序与伪标签各自设独立开/关对照，不在基础比较中捆绑所有因素。

不扩大旧小数据 loss/分辨率扫描。每个阶段只回答少数机制问题；未通过时检查数据支持和不确定性，而不是不断追加同一小池的重复更新。

## H100 多卡的充分实验设计

未来资源仍按至少 4×H100、48 小时的原规划估算，192 GPU 小时只是名义上限；实际节点、显存、互连和分配未确认。这不是新的启动或计时授权。

| 比较 | 数据规模与配对方式 | 主要问题 |
| --- | --- | --- |
| 数据学习曲线 | 按采集/装置分层的嵌套 25%、50%、100% 已准入训练池；全量臂优先 | 更多独立数据是否缩小训练/留出差距 |
| 编码器比较 | 选定配方的全量训练池，冻结 vs 部分适配；seed17/29/43 | 充分训练 head 后，适配是否仍有收益 |
| 跨来源比较 | 本域 vs 本域＋PanoMouse/其他已准入来源；共同端点只评分同语义点 | 外部数据是否增加本域及新采集泛化 |
| 机制补充 | 只有前项成立才做内部伪标签或时序开/关；完整成对 | 收益来自哪个额外机制 |

先测算成本再锁定矩阵；不是一次承诺所有组合。预算不足时减少完整比较项或学习曲线档位，优先保留全量训练臂及三个种子的完整处理/对照，不事后挑种子或只完成处理臂。单种子机制探索只作开发筛选，不能宣称三种子确认。

**充分训练的含义。** 预先登记全量采集遍历量、有效标注/无标签曝光、优化器更新、学习率、训练监测和终点，不沿用小池固定 4,000 更新就默认全量已收敛。区分两类问题：固定更新/样本预算比较数据多样性；按同一训练收敛规则、共同上限比较充分训练能力。后者资源可不同，需披露；不可混称等预算收益。没有达到预定覆盖或收敛的臂报告未完成，不以其失败否定路线。

**利用多卡的含义。** 小 head 优先并行完整配对、种子和折；全量多视角像素重编码/encoder 训练才按实测选择 DDP 等方案。先测 1/2/4 卡端到端吞吐、全局有效 batch、数据加载、通信、验证和存盘；GPU 利用率、显存或物理 batch 增大不代替有效样本/秒与科学结果。比较中同步曝光和全局更新，固定或另登记 batch/LR 调整，不能把扩 batch 当无关实现细节。

全量输入按来源/采集/视角/动作平衡采样并保留非底视回放；报告训练/开发曲线与实际重复次数。数据预处理和缓存按 split、发布/适配 encoder hash、预处理版本隔离；适配模型不能读取旧冻结特征代替像素重编码。集群任务不得因“吃满卡”访问测试或纳入无可靠监督的标签。

## 评价与交付

- 几何：旋转/平移方向、深度形状、尺度处理、预测相机＋深度和已知相机＋深度转移分别报告；已知装置与未知装置分开。
- 2D：先展示中位数、平均数、有效/缺失数量，再补 coverage、尾部和身份互换；按来源、采集、相机、部位、重叠拆分。原图像素和 704×768 参考坐标分别列，不混用。
- 所有有限误差保留；缺失/拒绝/非有限预测在全已知分母计 miss，均值若仅对可计算点需明确标注并给缺失率。诊断关注均值/中位数不改写既有冻结门槛；未来继续研究门槛与部署门槛分别预登记。
- 保留全部 seed17/29/43、失败和部分结果；模型/归一化/预测冻结后统一评分。选择配方只用开发集，最终确认使用未参与选法的新采集/装置。
- 报告学习曲线时以独立采集/装置及有效曝光为横轴；同时披露跨来源收益/退化、训练收敛状态和端到端 GPU 小时。预留原计划最终冻结评价/审计时间，不把全部额度消耗于优化。
