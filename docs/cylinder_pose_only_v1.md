# Cylinder 实例关键点头隔离对照 V1

## 锁定设计

接续 [物理视角平衡 V1](cylinder_view_balance_v1.md)，只新增一组 800 步 `pose_head_only`。原 `balanced_views` 800 步结果作为保留的外部对照，不重复训练。

- 与父实验完全相同的原始 768/15k 初始化、seed 17、lr=3e-6、优化器、每一步源场景、相机顺序/数量、分辨率、损失权重、梯度裁剪阈值和 88 项验证组合。
- 只允许 `instance_pose_head.*` 更新。这里的实例关键点头包含 objectness、box、mask、关键点、可见性等分支，不是仅更新坐标输出层。
- 冻结 encoder、共享 adapter、dense depth head 和未启用的 depth-pose bridge，并保持冻结模块 eval 模式。
- 保留原 loss 求和形式；深度 loss 因整个深度路径冻结，对可训练参数是常数，不提供梯度。
- 同为 800 次更新、1,800 张图像、3,540,384 个 patch token。固定最后一步，不改变现用权重，不选择开发集最佳 checkpoint。
- 原有 17 项验收门槛不变。新增隔离问题：`side_bottom`、`sides_bottom`、`sides_bottom_top` 的底视身体 NME 是否各比三者共同更新改善至少 5%；冻结深度指标差异须 <1e-6。
- 使用已知 Blender K/E，保留有覆盖率的 GT 框辅助三角化诊断；不将单目强行三角化。真实 Cylinder 数据仍不在本地。

这比较的是**可训练参数范围**，不是只改变一个 loss 的梯度符号。冻结模块也改变全局梯度裁剪的总范数，因此即便改善，也不能单凭这个对照证明某一个深度梯度就是原因。

## 实现与验证入口

- `tools/train_cylinder_pose_only.py`：仅在本实验进程选择冻结子类，旧模型/训练器源文件不修改。
- `configs/experiments/cylinder_pose_only_v1.json`：锁定配置。
- `tools/analyze_cylinder_pose_only.py`：旧门槛、逐组合配对结果、曲线和同一困难帧可视化。
- `tools/verify_cylinder_pose_only.py`：重建父协议、源/代码/权重哈希、逐步预算对齐、非 pose tensor 逐元素相等、深度指标不变。
- `tools/audit_cylinder_combinations.py`：相机组合覆盖审计，不只看顶/底视数量。
- 产物：`output/cylinder_pose_only_v1/`。

## 训练期间发现的组合覆盖偏差

复核上一轮由本项目新增的采样方案发现：`cylinder_order(..., variant=pose_index)` 将具体视角组合绑定到姿态编号。顶/底边际数量虽然增加，但不代表组合覆盖完整。

继承的 100 个 ClimbWall 双视图更新只有：`[0,7]`×20、`[1,6]`×17、`[2,7]`×14、`[3,6]`×24、`[4,7]`×10、`[5,6]`×15。底视 6 从未在双视图训练中与侧视 2 配对，而 WashFace `side_bottom` 验证恰好使用 `[2,6]`。16 个训练姿态各自的单目输入也始终固定为顶视或底视其中一种。

该问题是**采样组合覆盖偏差**，不是标签错误，也不是同一动作泄漏到训练/验证。当前隔离实验保留锁定日程，不在中途修改；它仍可比较同一日程下的参数更新范围，但不能据此把跨组合退化全部归为共享 adapter 的原因。

下一次采样实验应让组合/参考相机随访问次数变化，并与姿态编号解耦；在同一个训练源内覆盖每个侧视与顶/底的配对，不使用验证图像或标签训练。仍需保留未见组合的独立诊断项，区分“已见组合的姿态泛化”和“未见相机组合泛化”。

## 完成结果

800 步已完成，运行约 **193.9 秒**。初始化的全部验证指标与父实验差异为 0；88 项组合中所有深度指标变化也为 0。保存 checkpoint 的 **92 个非 pose 张量逐元素不变**，118 个 pose 张量发生更新。源数据、代码、原权重、配对日程及 checkpoint 重载核验通过，118 项 unittest 通过。

| 底视身体 NME ↓ | 原模型 | 三者共同更新 | 仅实例关键点头 | 相对共同更新改善 |
|---|---:|---:|---:|---:|
| 单底视 | 0.2980 | 0.1901 | 0.1897 | 约 0.2% |
| 侧＋底 | 0.1576 | 0.2056 | 0.1987 | 3.37% |
| 两侧＋底 | 0.1411 | 0.2002 | 0.1937 | 3.26% |
| 两侧＋底＋顶 | 0.1409 | 0.1926 | 0.1869 | 2.94% |

三个多视角组各 8/8 帧略有改善，但均未达到预先设定的 5% 改善要求，而且仍明显差于原模型对应多视角身体关键点表现。单顶视身体 NME 为 0.1648，与共同更新的 0.1635 接近。

原 Cylinder 侧视 PCK 为 0.4620（原模型 0.4973、共同更新 0.4538）；原双鼠 PCK 为 0.4830（原模型 0.5360、共同更新 0.4844），未恢复旧视角表现。原有门槛仍仅通过 **10/17**，不推广为现用模型。

冻结深度也意味着放弃本轮深度适应收益：例如单底视身体深度 AbsRel 保持原来的 0.2138，而共同更新版本为 0.0599。这不是冻结失败，而是实验设计的预期结果，不应把“深度不变”描述为深度改善。

视觉检查同一个预先选定困难帧 frame 55：仅 pose 与共同更新两行基本相似，鼻端、头部和前肢仍存在偏移；没有出现足以支持架构切换的明显改善。两条 pose loss 曲线也高度相似，末段仍下降，但仅凭训练曲线不能判断继续增加步数能否修复跨组合退化。

## 决策

**不支持仅靠冻结共享 adapter / 深度头解决问题，也尚不能证明共享特征更新是主要原因。** 相同日程下存在小幅、方向一致的影响，但作用有限，且只有一个 seed。

下一优先级由“继续拆分架构”调整为**相机组合采样修正**：

1. 新建采样版本，不改写本轮/父实验的锁定脚本与历史结果。
2. 让每个姿态跨访问轮次覆盖顶、底与侧视；具体侧视编号、是否顶/底以及参考相机顺序使用解耦的平衡日程，避免由 pose index 决定。
3. 在训练协议生成阶段强制输出相机对覆盖矩阵、每姿态单目覆盖、组合顺序覆盖；明确标记验证中的未见组合。
4. 先在相同 768、800 步预算下对照，不同步增加训练量、引入尾巴开关或换架构。修正采样后再决定是否需要子集一致性损失。

本轮结束后没有自动启动下一轮；原模型和原数据未修改。真实 Cylinder 仍需数据恢复后独立验证。
