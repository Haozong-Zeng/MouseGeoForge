**质量**：发布 3D 投影到 2D 的身体点误差中位数在各 session/层为 11–17 px（2704×2028）；离群阈值取训练 session 的 P99 = 81.5 px，原样用于开发和封存。发布 3D 由同批 2D 三角化而来，不是独立真值。

| 本项目 | PanoMouse | 依据 |

## 阶段 1：零训练跨装置检验（开发 session S03、S11）

**场地**：透明圆形平台立在支柱上，背景是杂乱、不对称的实验室（相机、支架、线缆），与 PyMouseStudio 的玻璃圆筒完全不同。

### 1. 轮廓掩码

S1 头在单张图像特征上推理；SAM2 用标注的身体关键点作提示（框 + 可见点）。参考是用全部视角 SAM2 掩码雕刻出的视觉外壳的投影（使用标定、外壳本身偏胖，只能做相对比较）。

| 层 | S1 原样 IoU | S1 清理后 IoU | SAM2 关键点提示 IoU | S1 清理后凸包偏差 |
| --- | ---: | ---: | ---: | ---: |
| 上层 | 0.648 | 0.711 | 0.612 | 181 px |
| 中层 | 0.688 | 0.725 | 0.703 | 73 px |
| 下层 | 0.548 | 0.644 | 0.683 | 342 px |

- **填充区问题被完整复现**：PanoMouse 是 4:3 图像，letterbox 到 512 后上下各有约 6.5 万像素的填充带，S1 在几乎整条填充带都预测为前景（各层中位 6.1–6.3 万像素），每张图 9–14 个连通域。推理时在 512 空间裁掉填充区后再反变换即可去除。
- 清理规则（保留最大连通域及距其 25 px 以内的连通域）后，S1 在上/中层与外壳参考一致性最好；下层仍差（穿过透明平台、黄铜支柱处出现条状误检）。
- SAM2 用关键点框提示时会把透明平台和背景带进掩码，凸包偏差 158–265 px，不适合作几何输入。

### 2. VGGT 相对位姿：原图 vs 只保留老鼠

每个时刻取 3 组“两个中层 + 一个下层”的相机组合，共 153 对中层、153 对下层。

| 输入 | 中层对 中位误差 / <5° | 下层对 中位误差 / <5° | 下层对落在 90/120/180° 附近 |
| --- | --- | --- | ---: |
| 原图 | 6.5° / 46% | 80.6° / 4% | 38% |
| 只保留老鼠（S1 清理掩码） | 21.3° / 2% | 108.2° / 0% | 66% |

- **PyMouseStudio 上“去背景”的结论不能迁移**：这里去掉背景反而全面变差。这个场地的背景杂乱、不对称，是有用的线索；老鼠在 2704×2028 的广角画面里很小，单靠老鼠信息不足。PyMouseStudio 的改善来自它特有的对称圆筒背景。
- **底视位姿问题在第二套装置上同样存在**（原图下层中位 80.6°），说明它不只是 PyMouseStudio 特有的问题。

### 3. 竖直消失点估计 up

| 层 | 误差中位数 | <2° |
| --- | ---: | ---: |
| 上层（408 视图） | 0.64° | 100% |
| 中层（408 视图） | 0.58° | 100% |

**结论可以迁移**，并且与 PyMouseStudio 侧视的 0.94° 一致。第一版参考（上/下层光轴平均）在 S03 少 2 台相机时产生约 6° 的系统偏差，结果显示 S03 全部约 6.3°、S11 约 0.75°；改用“上层相机中心所在平面的法向”作参考后两个 session 都在 1° 以内。第一版结果保留在 `vp.json`。

### 4. 轮廓极线相切求下层相机

VGGT 给出的下层先验在这里远超求解器的收敛范围，因此改为从标定加 5/10/15° 随机旋转出发（每档 3 次），相机中心由掩码质心初始化（不使用真值中心），初始位姿下切线无效的相机对剔除（由初值决定，不用真值）。共 504 次拟合。

| 掩码 | 起点 5° → 结束 | 起点 10° → 结束 | 起点 15° → 结束 |
| --- | --- | --- | --- |
| S1 清理，全部帧 | 4.9°（<5° 57%） | 8.8° | 11.4° |
| SAM2 关键点，全部帧 | 5.1° | 10.0° | 14.0° |

**极线相切法目前不能迁移到 PanoMouse**，求解基本停在起点附近。诊断：

- 目标函数本身有信号：在标定位姿处残差中位 23.7 px（S03 cam18）和 61.5 px（S11 cam23），旋转偏 5° 时升到 71–106 px、偏 10° 时 146–213 px。
- 但换用无导数优化（Powell、鲁棒中位残差）也不收敛，而且有的情况下拟合位姿的代价低于标定位姿（S03 cam20：10° 起点处 23.8 vs 标定 57.8），说明在当前掩码下存在比真值更低的错误极小值。
- 可能的原因：下层掩码质量（穿过平台，S1 下层一致性只有 0.64）；视频同步尚未核实；22–24 台相机中许多相机对接近相对（极点落在轮廓附近），约束病态。

## 总结

| 检验 | 能否迁移到第二套装置 |
| --- | --- |
| 竖直消失点估计 up | 能，0.6°（PyMouseStudio 0.94°） |
| 推理时裁掉 letterbox 填充区 | 必须做；填充区误检在新装置上同样出现 |
| 去背景改善 VGGT 位姿 | 不能，在 PanoMouse 上变差 |
| 轮廓极线相切求底视 | 目前不能，需要更好的下层掩码、同步核查和相机对筛选 |
| VGGT 底视位姿失败 | 两套装置都存在，是普遍问题 |

## 下一步（建议，未执行）

4. **2D 关键点（阶段 2）**：语义映射已基本确定，可以开始；后爪中点映射在训练前用细粒度足部点核对。
