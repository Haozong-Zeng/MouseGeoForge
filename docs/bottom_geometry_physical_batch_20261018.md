# 几何损失的物理 batch 与当前臂续训

2026-10-18，用户要求补齐几何损失batch支持，保持每次更新8个样本、采样顺序和损失归约，先验证数值/梯度一致性，再测试物理batch2/4并完整状态接入当前适配臂。输出 `output/pure_geometry_bottom_20261018_v2/resume_physical_batch/`。不启动冻结对照或关键点阶段。

## 泛化问题的判断

几何泛化需要样本内部有正确多视角约束，以及训练中覆盖不同rig、底视高度/方向、动物动作与外观；同一真实rig的重复标签不会因物理batch增大而变成新装置。有效batch决定每个优化器更新混合哪些样本和梯度，本轮一直固定8；物理batch仅决定同时计算几个样本。[PyTorch梯度累积说明](https://docs.pytorch.org/docs/stable/notes/amp_examples.html#gradient-accumulation)将有效batch定义为物理batch乘累积次数。

本模型没有BatchNorm，损失没有跨样本负样本或对比项，注意力在各自样本的多视图内进行。因而在精确算术下，batch1累积8次与将相同8样本分成batch2/4再累积，更新目标与梯度相同。此判断针对本地代码及固定采样，不声称物理batch本身改善底视泛化，也不声称混合精度和非确定性CUDA下未来轨迹逐位复现。[大batch泛化研究](https://openreview.net/forum?id=H1oyRlYgg)讨论改变有效batch的实验，不能直接作为本次固定有效batch打包的收益或退化证据。

## batch支持的边界

`tools/batched_geometry_20261018.py`将模型输出按样本切片，与该样本独立的标定、尺度、body/valid mask、可见对应点、rig角色一起计算原几何目标。复用经登记的原公式，不把不同样本误作额外相机，也不混合rig尺度。

第一版直接整网沿batch轴前向，固定预测测试通过，但真实模型BF16数值检查未通过：batch2/4的裁剪前梯度relativeL2为1.0619%/1.2577%，超过1%预登记门槛；transfer目标差也超过预登记阈值。该失败及源代码归档为 `*_v1_full_encoder*`，未接入正式训练。

该失败是对当前计算路径的数值门槛判断，不是独立验证退化证据，不能从中得出batch2/4泛化较差的结论。

第二版保留encoder的原始逐样本BF16算子路径，将四个缓存层的特征沿batch轴拼接，**仅相机和深度head在FP32下批处理**。encoder最后两层的autograd图仍连接，批处理head产生的每个样本梯度继续回流到对应encoder图。该策略避免多层BF16编码器因GEMM形状变化累计舍入差，不改变loss公式、参数集合或训练精度配置。encoder batch为1，geometry heads物理上限2/4，必须明确报告这个区别，不能称整个模型都变成batch4。

每个样本内部仍保持原来的body/background均衡、按视图/相机对的均值、有效对应点均值；缺失任务对该样本贡献0。**总目标始终为8个独立带权目标之和除以8**，不按有标签样本数重新归一，不按全batch有效像素数加权，不因实际物理组大小或最后尾组变化而改变权重。8样本后只裁剪一次、AdamW更新一次、EMA更新一次，LR和EMA继续原全局step。

只合并顺序相邻且视图数/图像形状相同的样本，batch2/4是物理上限。遇到1/2/3视图的不同包立即结束该物理组，不padding、不复制相机、不重排、不drop。报告实际物理组大小分布，不能将上限4冒充每次都4。原4个CPU workers、预取和独立worker RNG保持。

## 数值验证

先在32个实际训练样本、4个完整8样本更新上，使用固定预测，覆盖全部五类几何目标和六类来源。逐样本loss及预测梯度bitwise一致，总目标差≤1e-6；独立叶节点未连接的None梯度按数学上的0与batch切片产生的显式0比较，不将它解释成有效定位/几何监督。不同样本的body/有效点数量不共享分母。

随后从同一完整checkpoint，独立执行串行参考、串行重复、batch2、batch4各一次完整8样本更新。比较**裁剪之前**所有可训练参数的累积梯度、分项目标及单步后的参数/EMA，并验证RNG、采样曝光计数一致。预登记混合精度门槛：loss `atol1e-5 + rtol0.005`，梯度relativeL2≤0.01、cosine≥0.9999，更新后参数max_abs≤2e-6、relativeL2≤1e-6。先用严格固定预测测试隔离归约正确性，再用真实BF16模型测试实际数值误差；不依据独立验证分数修改门槛。

所有GPU测试权重丢弃，正式训练从原完整状态重载。原CUDA grid_sample backward已经证明非逐位确定，串行重复作为额外数值参照；不存在以测试更新推进正式采样进度的路径。

第二版真实模型已通过同一门槛：batch2/4累积梯度relativeL2分别`6.333e-5 / 6.494e-5`（0.00633%/0.00649%）；最大分项loss差`9.16e-7 / 1.375e-6`；单步参数max_abs`1.341e-7 / 9.686e-8`，模型relativeL2均<5e-9；RNG和曝光计数完全一致。串行重复的梯度relativeL2约`2.674e-5`。

## 保存与计时

当前4worker串行臂已在**2789次优化器更新**后安全保存退出。`source_checkpoint.pt`与`source_checkpoint.resume.json`保存raw参数、AdamW全部状态、EMA、Python/NumPy/CPU/CUDA RNG、loss weights、曝光计数、原schedule及下一更新/微批位置。先前2750备份另存以供恢复。原发布权重及14,912个source pins复核通过。

三种物理上限使用同一checkpoint、同一8样本更新序列，顺序1/2/4/4/2/1，每种重复两次；模型前后向、每样本几何目标、全局裁剪、AdamW及EMA均计入更新耗时，验证与checkpoint另计。采集显存allocated/reserved峰值及GPU利用率样本。

原计划4次warmup后计时12更新，但2789起点会让预登记的2801梯度诊断落入短计时窗。计时应先跨过该诊断再取连续普通更新；保留诊断本身，不为提速关闭或降频。任何计时窗修订均在GPU计时开始前登记并保留原修订及源代码哈希，不改变训练目标/采样/数值门槛。

实际修订为前12更新warmup（包含诊断2801），后12普通更新计时，每配置重复2次。独立记录诊断更新耗时，因为批处理图中逐样本梯度审计可能更贵；选择按99次普通更新＋1次诊断/100的**估计摊销耗时**，距最优3%以内的最小物理上限。普通更新直接观测值、诊断观测值和摊销估计分开报告，不混成整次实验墙钟加速。
