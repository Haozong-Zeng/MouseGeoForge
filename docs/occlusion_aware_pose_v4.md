# 遮挡感知第四阶段：两视角与四视角的分解诊断

2026-09-10。接续 [像素鲁棒核对照](occlusion_aware_pose_v3.md)。
**四视角直接推理未改善当前模型；先解决相机覆盖和输入视角数量的训练适应问题。**
本轮完成代码、24 场景 GPU 推理、几何对照、标签/相机核验和可视化。
未更新权重、训练、修改源数据或切换生产配置。

## 实现和控制条件

- `load_batch(record, num_views=2)` 保持两视角默认，四视角必须显式指定。
  增加诊断用 `diagnostic_view_order`，验证其是请求视角的完整排列，避免静默只取两个视角。
- 冻结推理函数支持传入专用 batch loader，既有调用行为不变。
- 四视角顺序固定为 `[2,0,1,3]`，前两个物理相机与原缓存 `[2,0]` 一致。
  VGGT 首视角位置保持不变。本文件相机 ID 均从 0 开始，对应文件名 00000000–00000003。
- 复用 V3 的 24 个开发场景，不声称是新的独立测试集或跨动物泛化。
- 768×432、原 checkpoint、均匀测量权重、3 px Huber、8 px 重投影门槛、5 次迭代
  全部固定。没有加 sigma 权重，也没有按预测可见性删点。
- 所有四视角方法复用**同一次四视角前向**。两个视角子集按物理相机 ID 选择，
  不假设张量下标就是相机编号。
- 实例对应仍用 GT 框辅助的 query 匹配；逐视角实例 ID 一致性已核查，
  不将该结果当作端到端多鼠关联/检测性能。
- 两视角和四视角 loader 的 median-baseline 归一化尺度可以不同；
  已还原为毫米比较世界坐标和外参，核查共享相机内参及二维标签相同。

三组主比较和一组预先声明的诊断过滤：

| 组别 | 模型输入 | 三角化观测 | 用途 |
| --- | --- | --- | --- |
| A | 两视角 | 原两视角 | V3 均匀基线，逐点结果完全复现 |
| B | 四视角 | 仍只用原两视角 | 隔离更多图像上下文的影响 |
| C | 与 B 同一次四视角前向 | 四视角 | 固定二维输出后比较几何冗余 |
| D | 与 C 相同 | 只保留 C 中 ≥3 个最终内点的解 | 区分两点支持与真正更多观测的一致性，不重拟合 |

主对照 C vs B，门槛沿用前轮：覆盖率最多下降 3 个百分点，交集点均值/P95
不超过参考的 1.01/1.05 倍。B vs A 是上下文控制，C vs A 是整体诊断。
协议在推理前锁定，不根据结果调门槛。

## 结果：更多图像上下文没有直接改善当前坐标头

在原来两个物理相机的相同 2,208 个二维标签上：

| 指标 | A：两视角输入 | B：四视角输入 |
| --- | ---: | ---: |
| 平均像素误差 | 18.2817 px | 24.1008 px |
| 框对角线归一化误差 NME | 0.12618 | 0.15849 |
| GT 框匹配 PCK@0.1 | 54.39% | 42.57% |
| 可见点平均误差 | 18.3559 px | 24.2532 px |
| 遮挡点平均误差 | 17.7710 px | 23.0516 px |

不是只有遮挡点变差；可见点也明显受影响。PCK 是 GT 框匹配后的诊断，
不是将未检出实例计入的端到端 PCK。

## 结果：三角化高覆盖率不等于高可靠性

| 组别 | 有效点 / 1,104 | 覆盖率 | 各自支持点平均误差 | P95 |
| --- | ---: | ---: | ---: | ---: |
| A | 804 | 72.83% | 10.7444 mm | 27.3381 mm |
| B | 629 | 56.97% | 13.5606 mm | 28.5643 mm |
| C | 1,064 | 96.38% | 22.8164 mm | 57.3460 mm |
| D | 147 | 13.32% | 14.0840 mm | 29.3956 mm |

各组支持点集合不同，必须再看相同点：

- B vs A，共同 559 点：A **9.4633 mm** → B **13.3397 mm**，上下文控制未通过。
- C vs B，共同 629 点：B **13.5606 mm** → C **18.5757 mm**，主对照未通过。
- C vs A，共同 787 点：A **10.6216 mm** → C **20.9722 mm**，整体比较未通过。

C 的最终内点数分布：40 点拒绝，**917 点仅 2 个内点**，142 点 3 个内点，5 点 4 个内点。
所以 96.38% 覆盖主要不是四个观测达成一致。D 只是筛选 C，交集坐标完全相同，
不能把其均值下降称为三维预测本身改善。
相对 A 新支持的 277 点平均误差 28.0562 mm、P95 69.9890 mm。

## 相机、单位和标签核验

后验只读审计 `tools/audit_view_redundancy.py`：

- 所有 4,416 个 GT 二维坐标与 GT 三维点通过相机投影吻合：
  平均误差 **0.000036 px**、最大 **0.000126 px**。
- 用 GT 二维坐标做四视角三角化，1,104 点全部成功；
  平均误差 **0.000017 mm**、最大 **0.000041 mm**。
- 因此本批数据的相机/世界坐标/毫米单位/二维标签内部一致，
  没有证据将这次退化归咎于相机错配或毫米缩放错误。
- 此核验不等价于证明每个标签的解剖语义或原 Blender 求值都完美；
  第一阶段仍未补齐遮挡原因的 24 帧状态没有改变。

四视角前向中，各相机的表现也不均衡：

| 相机 ID | 平均二维误差 | NME | 48 个 GT 实例中满足 score≥0.5、IoU≥0.5 的数量 |
| --- | ---: | ---: | ---: |
| 2（原视角） | 16.0110 px | 0.13527 | 40 |
| 0（原视角） | 32.1907 px | 0.18171 | 22 |
| 1（新增视角） | 35.6064 px | 0.24352 | 17 |
| 3（新增视角） | 54.8549 px | 0.47400 | 9 |

训练清单核查发现：当前 checkpoint 的 **200 个双鼠训练场景全部使用 `[0,2]` 相机对**。
它没有在这些双鼠训练场景上学习相机 1/3，也没有用四视角输入训练该姿态头。
这使“额外视角覆盖不足 + 四视角上下文分布变化”成为优先排查的训练问题；
本次实验并未进一步将两者的因果贡献分离，不能断言只训练其中一项即可解决。

## 视觉检查

按共享视角 NME 增幅自动选出最差的 frame 216，未挑选成功样例：

- 顶视相机 0：两视角输入的预测虽有误差，仍大致分布在两只鼠各自身体；
  四视角输入后，很多预测聚到两鼠之间/邻接区域，部分清晰可见身体和尾部明显失配。
- 侧视相机中，肢体附近点也有偏移，新增相机 1/3 并未形成可靠补充。
- 这不是仅靠剔除不可见点能解决的现象，检测/query 区分和可见点定位同样需要适应。

## 下一步建议：修正训练视角覆盖，而非直接增加原相机对的训练步数

先用原训练来源的小子集做有界适应对照，不让这些已查看的开发场景回流训练：

1. 固定两视角数量，随机覆盖四台相机的六种相机对，检查新增相机 1/3 的二维性能。
2. 在相同视角覆盖基础上加入 2/4 视角混合输入，检查四视角上下文适应与旧两视角性能保持。
3. 重复 A/B/C 分解评估；只有二维和共同三维点不退化后，再试不确定性权重。

对照要同时记录训练步数、总图像数/编码 token 数和 GPU 时间；不能把四视角每步
看到两倍图像与纯架构改进混为一谈。首视角/相机排列随机化需要记录并测试，
不能在同一比较中无记录地改变。最终提升需另设未查看的来源/动物或数据划分验证。
本轮尚未启动这些微调，也没有改写旧训练清单；生产继续保持当前两视角设置。
