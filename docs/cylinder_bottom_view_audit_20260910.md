# Cylinder 底视图专项诊断（2026-09-10）

## 范围与结论

用户指的是此前**真实 Cylinder** 的底视图测试；该真实数据集目前不在本地。因此本轮没有复测它，不以 Water Reaching 或合成 Cylinder 替代真实结果。以下全部新数字来自本地 **Blender 合成 Cylinder**，只用于定位训练/验证缺口与构建复测流程。

结论：优先补齐 Cylinder 底视图验证与按物理视角采样，而不是继续尾巴曲线实验或直接扩大原训练步数。不能据本次结果判定“VGGT 完全不会底视图”，也不能证明其预训练底视图占比接近零。局部单目深度、跨视角相机估计、下游关键点头需要分开检查。

## 1. 相机方向与实际训练覆盖

从 OpenCV world-to-camera 外参计算光轴 `R.T @ [0,0,1]`；仅对 Blender Z-up 世界使用 `elevation=asin(-forward_z)` 分类。相机编号不是全项目通用的物理视角。

|---|---|---|---|
| Cylinder ClimbWall / WashFace / WalkAround | id 6，Camera.007 | id 7，Camera.008 | ClimbWall/WashFace 的 [0,2] 均为侧视 |

- 400 个训练场景、800 张所选图像：顶视 284，侧视 432，底视 **84（10.5%）**。

## 2. 冻结模型对照

数据：合成 `PyMouseStudio-BrownFur-WashFace-Core23` 的帧 **1、49、91**，属于原有验证动作组。分辨率 **768×768**。模型：原始 768/15k `seed17_off/final_heads.pt`，以及原版 VGGT-Omega 深度/相机头。没有训练、更新权重或改写数据。

五种输入：侧视 `[2,0]`；侧视＋底视 `[2,0,6]`；侧视＋顶视 `[2,0,7]`；单底视 `[6]`；侧视＋底视两张 `[2,6]`。每个组合重新编码 RGB，不切片复用其他组合的上下文特征。原版与当前头共享同一组合的冻结 encoder 特征，但原版头不经过已训练 adapter。

深度监督在所有组合中固定使用原始侧视 `[2,0]` 的基线单位，避免改变相机数量时重定标 GT。侧视基线各项指标与原保存验证结果一致（差异 <1e-6）。33 张输入视图的 3D→2D 标签投影最大误差 **0.000244 px**。新增相机方向单元测试 **5/5** 通过。

### 原版 VGGT-Omega：区分单目形状与多视角融合

原版深度没有已知毫米尺度。下面的深度误差按每张图 GT 身体区域做**独立中位数尺度对齐**，只是 oracle 形状诊断，不是实际可部署精度；身体区域由 GT mask 提供，不代表模型分割能力。

| 底视输入方式 | 3 帧底视深度 Spearman（越大越好） | 平均尺度对齐 AbsRel |
|---|---|---:|
| 单底视 | 0.802 / 0.800 / 0.468 | 0.0156 |
| 一个侧视＋底视 | 0.527 / 0.692 / 0.301 | 0.0257 |
| 两个侧视＋底视 | 0.150 / **−0.248** / −0.017 | 0.0359 |

视觉复核 frame 49：单底视时能恢复身体前部较远、后部及尾巴较近的部分趋势；三视图上下文中，原版底视的头尾深度关系出现明显错误。当前头的单底视关键点还存在整体偏移，不能靠关闭尾巴解决。

常量 GT 中位数深度的身体 AbsRel 本来就只有 0.0161 / 0.0342 / 0.0155。小鼠表面起伏相对相机距离很小，**低 AbsRel 不足以证明身体形状正确**；需同时看身体深度排序、中心化形状误差与可视化。

相机头也存在明显问题：三视图中的底视相对旋转误差为 **93.5° / 176.3° / 134.3°**。但仅两侧视时相对旋转误差也达 **92.2° / 96.9° / 96.1°**，所以问题不只发生于底视。重复圆柱结构、透明/反光玻璃、宽基线与局部可见表面差异可能共同造成匹配困难；这是待检验的解释，不是已证明的因果。

## 3. 预训练数据说法的证据边界

[VGGT-Omega 论文 §3.5](https://arxiv.org/html/2605.15195v1#S3.SS5) 列出多种公开室内、室外、物体、合成及动态数据，并包含内部数据和网络视频。论文没有给出“实验鼠透明 Cylinder 腹侧视图”的数量或占比。因此将真实 Cylinder 底视图视为**疑似分布外输入**是合理的工作假设，但“几乎不存在”尚不能从公开资料或本轮合成测试定量证实。

## 4. 下一步优先级

1. **补验证，不先拉长训练**：增加独立 `cylinder_bottom`、`cylinder_top`、`cylinder_side` 指标与组合验证。继续保持动作/源视频分组，不能把同源连续相邻帧分别当独立训练与验证。
2. **使用已知标定**：固定相机任务优先输入真实/Blender 标定 K、E；不要让 VGGT 相机头的高误差污染三角化或伪深度监督。已知外参本身不会自动修复 encoder 内的跨视角注意力，需分开验证。
3. **后续小规模对照**：物理视角平衡采样＋保留侧视回放；比较联合编码与“每视图独立提取→依据标定和质量进行融合”。单目分支可作为缺视角/不可靠融合时的回退。不要永久删除底视图——它对腹部和爪部本来有价值。
4. **真实复测留待数据恢复**：同帧、同裁剪、矫正后的底视／侧视／混合输入，检查身体深度排序、预测相机与真实标定偏差、关键点可见性和重投影误差。当前没有该真实数据，结论仍未验证。
5. **多鼠尾巴可选关闭**：按用户允许，将多鼠不输出/不监督尾巴作为后续配置路线，保留原始 Core23 标注与单鼠尾巴能力；必须一致处理监督、匹配、推理有效位和身体-only 报告。本轮未实施该开关、未更改原指标或重新开启训练。
