# 分辨率对照：256 → 512

2026-09-10。用户授权先提高输入分辨率；先执行 2 倍边长，不同时改模型结构、裁剪、
数据量、增强、损失或训练步数。768×432（3 倍）已支持尺寸计算，但本次不自动启动。

## 固定协议

- 对照：已完成的 `depth_pose_baseline_5000_v2`，双鼠 256×144，单鼠 256×256。
- 本轮：`configs/experiments/depth_pose_resolution_512_v1.json`，双鼠 **512×288**，
  单鼠 **512×512**。直接从原始文件缩放读取，并重新提取冻结 encoder 的 RGB 特征，
  不对旧缓存或低分辨率图片插值充当新增细节。
- 同一 seed17、同一原始 Omega checkpoint、64 train / 32 val、相同 2 个相机、
  5000 步、AdamW 1e-4、相同损失（local heatmap 辅助 loss=0，depth+pose 均训练，
  bridge off），从头初始化，不从 256 checkpoint 续训。
- 每 500 步训练集评估，最终固定步数验证，不用验证集挑 checkpoint。
- 边长翻倍意味着像素数和 patch 数约 4 倍，不等于计算时间只翻倍。
  这是等更新步数对照，不是等计算量对照。
- 模型窗口半径仍为图像归一化坐标 .1，架构超参数不变。

## 启动前验证

`tools/audit_pose_resolution.py` 已核对全部 96 个新旧输入对：配置除说明字段外仅
long_side 不同，源场景与分组完全相同；world scale、外参、实例 ID、归一化 UV
不变，内参前两行乘 2，关节点重投影误差 <.01 新分辨率像素，深度表面 anchor
对齐审计通过。离散 mask/框边缘允许因重新采样而变化。

实际相机顺序取 batch 的 view_ids；选取 [0,2] 后加载顺序是 [2,0]，不能直接把
张量轴索引当相机编号。双鼠 0=顶视、2=侧视。

## 验收要求

1. 新旧运行的初始权重哈希和训练顺序哈希必须相同；初始验证指标因分辨率变化
   可以不同。最终 checkpoint 需独立重载复算全部 32 验证场景。
2. 分开报告单/双鼠、train/val 的 NME、计漏检 PCK、检测和鼠体深度误差；
   不用绝对像素误差直接跨分辨率比较。检测框 IoU 含离散 mask 边缘差异。
3. 对照双鼠困难帧 40、98、246、393，检查实例重复定位、尾部缩短和四足偏移，
   不能只挑效果好的图。原困难样本分析位于 `output/dual_mouse_diagnostic_v1/`。
4. 只有本轮结果支持时再讨论 768 或实例裁剪；不把分辨率预先认定为唯一原因。
   本轮单种子，仍共享合成资产，不声称真实动物泛化。

输出：`output/depth_pose_resolution_512_v1/`，原 256 结果不覆盖。
状态：从源码提交 `c629543` 启动的正式训练已完成并通过重载验收。
本次验收后暂停自动复查，未启动 768 或任何额外训练。

## 最终结果（2026-09-10）

新旧初始权重 SHA256 与 5000 步采样顺序 SHA256 完全相同；512 模型独立重载后，
全部 32 验证场景的逐场景指标最大差异为 **0**。训练及最终评估用时 22.9 分钟，
256 基线为 18.7 分钟（不含独立重载验证；各次运行 GPU 负载不完全相同，非严格速度基准）。

| 分组 | 指标 | 256 | 512 |
|---|---|---:|---:|
| 单鼠训练 | NME ↓ | .0184 | .0214 |
| 双鼠训练 | NME ↓ | .1103 | .1095 |
| 单鼠验证 | NME ↓ | .1470 | .1097 |
| 单鼠验证 | 计漏检 PCK@.1 ↑ | 31.52% | 52.04% |
| 双鼠验证 | NME ↓ | .2089 | .2061 |
| 双鼠验证 | 框匹配 PCK@.1 ↑ | 26.90% | 27.11% |
| 双鼠验证 | 计漏检 PCK@.1 ↑ | 21.13% | 18.41% |
| 双鼠验证 | 检测 recall ↑ | 57.81% | 54.69% |
| 双鼠验证 | 匹配 mask IoU ↑ | .5157 | .6794 |
| 双鼠验证 | 尾部 NME ↓ | .2668 | .2717 |
| 双鼠验证 | 鼠体 depth AbsRel ↓ | .0393 | .0372 |
| 单鼠验证 | 鼠体 depth AbsRel ↓ | .1448 | .1030 |

两个验证来源等权的 NME 从 .1779 降至 .1579，计漏检 PCK 从 26.32% 升至 35.22%，
鼠体深度 AbsRel 从 .0921 降至 .0701，mask IoU 从 .6525 升至 .7831。
但平均姿态改善主要来自单鼠，不能用这个总平均宣称解决了双鼠问题。
双鼠全图深度 AbsRel 反而从 .0433 升至 .0513，不能只看鼠体区域。
跨分辨率 mask/深度指标还受到预测网格和离散 GT 重采样影响。

### 固定困难帧视觉核对

已逐一比较新旧模型的训练帧 40/98、验证帧 246/393，每帧侧视和顶视：

- 40：高分辨率深度的鼠体/尾部轮廓更清楚，但顶视两鼠骨架仍收缩在身体内，
  尾巴与四足并未随像素增加而充分展开。
- 98：顶视棕鼠尾部仍遗漏/缩短，身体点聚集；并非普遍的精细姿态恢复。
- 246：顶视仍有整体位置偏差和严重尾部收缩，两鼠分开也会失败。
- 393：侧视部分骨架范围有所展开，但顶视预测仍聚到两鼠之间或黑鼠附近，
  未恢复两套清楚对应各自鼠体的骨架。该图颜色是框匹配结果，不是身份追踪证据。

高分辨率 RGB 确实保留更多细节，深度鼠体边缘也更清晰，但双鼠关键点解码并未
有效利用这些新增细节到足以解决失败的程度。此处是对输出的观察，不是特征机制定论。

### 解释与下一步建议（未执行）

1. 本轮支持更高分辨率对部分任务有益，**不支持分辨率是当前双鼠唯一/主要已证实根因**。
   但也不能据此断言 768 永远无效。
2. 512 双鼠训练 NME 在 3000/4000/4500/5000 步为 .184/.138/.143/.110，
   后段仍在改善；256 对应约 .148/.117/.113/.110。等更新预算不等于两者都充分收敛。
   建议暂保留 512，先注册相同数据下的更长预算/学习率衰减对照，检查收敛程度；
   若再比较分辨率，应两组使用共同优化预算与策略，不能只调优 512 后归因于分辨率。
3. 并行的设计方向仍是实例定位与实例内部姿态解码的分工（实例相对坐标/ROI 特征），
   用困难训练样本检查“框找对但骨架收缩”问题，作为独立变量实验，不与分辨率一起改。
4. 数据仍需更丰富的朝向/位置/姿态覆盖，但不可把本次困难验证帧挪进训练再沿用
   同一个验证成绩。当前只有单种子、共享合成资产，未进行显著性或真实动物评估。
