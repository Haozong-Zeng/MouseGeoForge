# 多目标检测：已有路线与MouseGeoForge后续设计

2026-09-12，基于论文及官方仓库；本轮只调研/准备验证，不训练新架构。

## 核心判断

已有检测器通常联合学习“哪里可能有目标、框如何定位、是否为独立目标”，
并以多尺度特征、匹配和适当分类/回归损失配合。我们最近的冻结6/12框加
小评分器，只覆盖其中一部分，不能用其失败否定DETR、CenterNet或多目标检测。
也不能把“每框IoU高”自动等同“一鼠一框”；最后一组覆盖标签实验恰好显示，
训练正标签增加而开发重复/漏检更差。

## 典型做法

|路线|候选/定位|重复与监督|对本项目的意义|
|---|---|---|---|
|Faster R-CNN/Mask R-CNN系|RPN产生候选，区域特征再分类和框回归；可接实例mask|多候选学习，使用NMS等后处理|清晰可解释的检测→ROI姿态基线|
|CenterNet系|中心热图加offset/size回归|峰值选择与联合中心/几何训练|轻量候选生成器；不是冻结粗网格后只重打分|
|DETR/DINO系|query代表候选实例，decoder预测并细化框|一对一集合匹配；DINO加去噪训练/混合query选择等|最接近现有Transformer架构的长期路线|
|RT-DETR系|高效多尺度特征、query选择、decoder框预测|端到端匹配；官方实现提供IoU质量感知VFL|参考分类分数与框质量对齐，不能只移植loss名称|
|YOLOv10系|密集预测与框回归|训练同时一对多/一对一分支，推理采用一对一以免NMS|把训练信号丰富度与推理唯一性分开设计|

Faster R-CNN的RPN共享特征并联合预测候选objectness和框；官方Detectron2
RPN进一步展示标签匹配、框回归和候选筛选。参见
[论文](https://arxiv.org/abs/1506.01497)、
[官方RPN](https://github.com/facebookresearch/detectron2/blob/main/detectron2/modeling/proposal_generator/rpn.py)。

CenterNet用中心点回归尺寸/其他属性；本项目stride16、局部小头并不是论文
完整多尺度高分辨率实现。候选中心相近时，粗网格和局部峰筛选可能合并，
后续评分不能重新创造被丢弃的实例。参见[论文](https://arxiv.org/abs/1904.07850)。

DETR将检测作为一对一集合预测；DINO结合去噪锚框训练、混合query选择和
框预测改进。这里的DINO是检测器，不能与VGGT继承的自监督DINO encoder
混淆。参见[DETR](https://arxiv.org/abs/2005.12872)、
[DINO论文](https://arxiv.org/abs/2203.03605)、
[官方DINO模型](https://github.com/IDEA-Research/DINO/blob/main/models/dino/dino.py)。

RT-DETR官方criterion中VFL正目标是匹配框IoU，负项用预测分数加权，同时
有L1/GIoU回归。与当前均值BCE、永久固定候选框的条件不同，不能直接声称
换VFL必然解决问题。参见[论文](https://arxiv.org/abs/2304.08069)、
[官方criterion](https://github.com/lyuwenyu/RT-DETR/blob/main/rtdetr_pytorch/src/zoo/rtdetr/rtdetr_criterion.py)。

YOLOv10采用一致双分配；官方head中一对多和一对一输出分开，推理/导出用
一对一结果。其多分支梯度处理也是方法的一部分，不等于简单加两份BCE。
参见[论文](https://arxiv.org/abs/2405.14458)、
[官方head](https://github.com/THU-MIG/yolov10/blob/main/ultralytics/nn/modules/head.py)。

## 对上一轮的具体解释

1. 两个高分query都覆盖黑鼠时，NMS可以减少重复，但不会凭空生成棕鼠。
   NMS本身是合理基线，不应禁用；只是必须同时报告第二鼠召回，而非把
   预测数减少当成“解决实例分离”。严重重叠时还需测NMS误删的代价。
2. 中心与原query的合并几何容量63/64说明信息互补；实际最高48/64说明
   候选选择/特征/目标函数还没把容量转化为可靠输出。63是GT辅助上限。
3. ROI均值/最大池化会弱化细粒度布局，近似重复框描述子很相近；位置编码
   或关系层并不保证能区分哪个候选应负责哪只动物。
4. 训练单鼠损失下降而正例分数变低，不能凭平均BCE/MAE判断还需加预算。
   应分正负例、目标尺寸、视角、遮挡、真实/合成域检查召回和校准。
5. 16双鼠训练姿态依然很少；多个相邻帧与摄像机不等于独立行为/动物来源。
   新真实验证先建立，但本次圆筒是单鼠，不能替代真实双鼠验证。

以上是结合本地实验的分析，不是已证明唯一因果关系。

## 推荐实施次序：先标准基线，再联合架构

### A. 验证与标注先固定

使用新PyMouseStudioRaw来源划分，补A底视人工框/关键点及侧视复核。
先确认原视频镜头处理、相机同步、框是否含尾巴和标签来源。旧88开发仅
回归，GR2/UR2/UR3保持锁定；真实双鼠另外选独立来源，不能假称此处已解决。

### B. 做可解释的定位基线

在相同数据/分辨率/训练预算上，比较标准检测头（区域候选+框回归，允许
明确标注的NMS基线）与当前query头。先判断768长边下是否稳定找全鼠体，
单鼠与双鼠分开报TP/FP、AP/AR、重复、遮挡/小目标/底视分层结果。标注不
完整图像不能将所有未匹配框当背景；只用有资格的标签计算accuracy。

### C. VGGT多尺度特征→实例decoder→框/置信度联合预测

保留768及1–N视角，先冻结VGGT和深度路径；使用原query/中心候选作为初始化，
加可学习的box residual而非固定框重评分。匹配基于当前预测的类别与L1/GIoU，
逐层框细化可有辅助监督。一个对照只改变一项；先框细化，再单独测试
质量感知分类，最后才考虑去噪/一对多辅助监督。检查OFF兼容与深度保留。

### D. 实例ROI关键点与跨视角身份

每个实例用自己的ROI特征预测关键点、可见性及不确定度，再做跨视角关联。
新中心候选不能直接借另一query的旧关键点/mask；跨相机query编号也不是
天然同一只鼠。多视角可用标定与重投影一致性协助匹配，单视角必须能独立
运行；不可见点不等于缺少标注，likelihood不等于可见性。

ROIAlign只是采样已有特征，不能恢复encoder粗网格已经丢失的细节；若足部
误差仍受分辨率限制，应另做“原图ROI二次编码/高分辨率局部分支”对照，
而不是只把输出热图上采样后宣称增加信息。

### E. 时序关联后置

检测与追踪是不同任务。ByteTrack利用与已有轨迹的关联保留部分低分检测，
可减少遮挡时的轨迹断裂，但不是给一张图创造完全缺失目标的保证。
参见[ByteTrack论文](https://arxiv.org/abs/2110.06864)。固定相机可复用标定、
运动约束与实例记忆；只能在可靠连续短段启用，不能把不同动作拼帧当连续
轨迹，也不能以时序平滑掩盖单帧定位失败。

本轮未下载检测器权重、训练新头或选择新checkpoint。下一次实施应先完成
真实标注资格，再做B/C的最小对照；不继续在旧开发集上叠加冻结框评分机制。
